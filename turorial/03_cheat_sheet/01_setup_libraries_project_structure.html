Mục 1: Cấu Hình Thư Viện Chuẩn (pubspec.yaml) & Cấu Trúc Dự Án Sẵn (lib/)

Tài liệu này cung cấp toàn bộ file cấu hình pubspec.yaml chuẩn xác 100% của dự án mẫu (không sai lệch một phiên bản nào), cây cấu trúc thư mục lib/ đầy đủ các module và file điểm khởi chạy main.dart.

Danh mục nội dung:
  • 1. Toàn bộ file cấu hình pubspec.yaml chuẩn mẫu (Copy & Dán đè)
  • 2. Giải thích chi tiết từng thư viện: Là gì, dùng để làm gì, dùng thế nào & vì sao?
  • 3. Cấu trúc cây thư mục lib/ chuẩn của dự án mẫu
  • 4. Giải thích vai trò của từng thư mục và file trong dự án
  • 5. Toàn bộ mã nguồn file main.dart (Khởi động & Session Gatekeeper)
  • 6. Giải thích chi tiết code main.dart: Dùng để làm gì, dùng thế nào & vì sao?
  • 7. Lệnh Terminal khởi tạo nhanh dự án, thư mục và cài đặt thư viện

2. Giải Thích Chi Tiết Từng Thư Viện: Dùng Để Làm Gì, Dùng Thế Nào & Vì Sao?

1. sqflite: ^2.4.2 & path: ^1.9.1

  • Dùng để làm gì? Cung cấp hệ quản trị cơ sở dữ liệu SQLite cục bộ (offline) trên thiết bị di động (Android / iOS). Đi kèm là path giúp nối đường dẫn thư mục lưu trữ file database an toàn trên mọi hệ điều hành.
  • Dùng thế nào? Gọi openDatabase(join(await getDatabasesPath(), 'exam_app.db')) trong class DatabaseHelper để tạo bảng, thực hiện các thao tác CRUD (insert, query, update, delete).
  • Vì sao? Đề thi PE luôn yêu cầu dữ liệu phải được lưu trữ bền vững (persistent), tắt ứng dụng mở lại vẫn còn nguyên dữ liệu, không bị mất đi như khi lưu biến trong bộ nhớ RAM.

2. sqflite_common_ffi_web

  • Dùng để làm gì? Là cầu nối giả lập SQLite trên nền tảng Web Browser (Chrome/Edge) thông qua WebAssembly (Wasm) và IndexedDB.
  • Dùng thế nào? Trong DatabaseHelper._initDatabase(), sử dụng cờ if (kIsWeb) để gọi databaseFactoryFfiWeb.openDatabase('exam_app.db') thay cho phương thức di động thông thường.
  • Vì sao? Trong phòng thi, máy ảo Android (AVD) thường rất nặng, dễ giật lag hoặc bị treo. Chạy app trực tiếp trên Google Chrome giúp tốc độ build nhanh gấp 5-10 lần và kiểm tra giao diện tức thì. Nếu thiếu package này, app sẽ crash ngay lập tức khi chạy lệnh SQLite trên trình duyệt.

3. shared_preferences: ^2.5.4

  • Dùng để làm gì? Lưu trữ dữ liệu dạng Key - Value cục bộ siêu nhẹ, dùng quản lý phiên đăng nhập (Session Management).
  • Dùng thế nào? Lưu trạng thái đăng nhập qua prefs.setBool('isLoggedIn', true) và prefs.setString('username', username). Khi Logout gọi prefs.clear().
  • Vì sao? Tiêu chí chấm điểm của đề thi có Task "Ghi nhớ trạng thái đăng nhập": Khi app khởi động, nếu đã đăng nhập thì vào thẳng HomeScreen, chưa đăng nhập thì hiển thị LoginScreen/RegisterScreen.

4. flutter_riverpod: ^3.2.0 & riverpod_annotation: ^4.0.1

  • Dùng để làm gì? Hệ thống quản lý trạng thái (State Management) chính quy của Flutter, đồng bộ dữ liệu giữa các màn hình và tự động render lại UI.
  • Dùng thế nào? Bọc toàn bộ app bằng ProviderScope tại hàm main(). Khai báo @riverpod trên class Notifier và sử dụng ref.watch(itemProvider) trong widget.
  • Vì sao? Giải quyết bài toán: Sau khi thêm mới hoặc chỉnh sửa dữ liệu ở màn hình Add/Edit, màn hình HomeScreen lập tức tự động cập nhật lại danh sách mà không cần truyền dữ liệu lòng vòng qua tham số hoặc setState thủ công.

5. http: ^1.2.0

  • Dùng để làm gì? Gửi HTTP Request (GET, POST, PUT, DELETE) lên REST API bên ngoài.
  • Dùng thế nào? Gọi http.get(Uri.parse(url)), giải mã JSON bằng jsonDecode(response.body).
  • Vì sao? Dự phòng khi đề thi yêu cầu nạp dữ liệu từ Mock API Online (như MockAPI.io, Reqres) thay vì SQLite thuần túy.

6. build_runner & riverpod_generator: ^4.0.2 (dev_dependencies)

  • Dùng để làm gì? Công cụ sinh mã tự động (Code Generator) tạo ra file *.g.dart cho Riverpod.
  • Dùng thế nào? Sau khi viết xong file provider, mở Terminal gõ lệnh: dart run build_runner build --delete-conflicting-outputs.
  • Vì sao? Tiết kiệm tối đa thời gian viết boilerplate thủ công, code ngắn gọn, tự động sinh type-safe provider và xử lý AsyncValue (loading, error, data).

7. dependency_overrides: test_api: ^0.7.9

  • Dùng để làm gì? Ép phiên bản thư viện test_api tương thích với Flutter SDK.
  • Vì sao? Ngăn ngừa lỗi xung đột phiên bản phổ biến (Version Solving Conflict) giữa Flutter SDK hiện tại và riverpod/flutter_test khi chạy flutter pub get.

4. Giải Thích Vai Trò Từng Thư Mục & Từng File: Dùng Để Làm Gì? Vì Sao Tách Như Vậy?

Thư mục / File Dùng để làm gì? Vì sao cần tách riêng?
lib/models/
(user.dart, item_example.dart)		 Định nghĩa cấu trúc dữ liệu kiểu OOP: các thuộc tính, constructor, fromMap() và toMap(). Giúp code tường minh (type-safe), tránh lỗi gõ sai tên trường String khi làm việc với SQLite và UI.
lib/utils/database_helper.dart Thực hiện mở kết nối SQLite (hỗ trợ cả Mobile & Web Chrome), tạo bảng, nạp JSON tự động và cung cấp toàn bộ hàm CRUD. Áp dụng Singleton Pattern, toàn bộ truy vấn gom về 1 nơi, các màn hình chỉ việc gọi hàm mà không viết lại câu lệnh SQL.
lib/utils/app_validator.dart Tập hợp các hàm static validate dữ liệu cho Form: rỗng, username, password, confirm password, email regex, số dương. Tái sử dụng ở mọi màn hình (Login, Register, Add, Edit). Chỉ cần gán tên hàm vào thuộc tính validator: của TextFormField.
lib/services/session_service.dart Lưu trữ và đọc cờ đăng nhập isLoggedIn, username qua SharedPreferences. Tách riêng nghiệp vụ phiên người dùng khỏi UI, hỗ trợ kiểm tra điều hướng ngay khi app khởi động tại main.dart.
lib/providers/item_provider.dart Quản lý State danh sách items bằng Riverpod Code Generator (@riverpod). Tự động cập nhật giao diện của HomeScreen ngay khi thêm, sửa hoặc xóa dữ liệu mà không cần gọi setState thủ công.
lib/utils/app_theme.dart Định nghĩa ThemeData cho 2 chế độ: Sáng (Nền Kem, Tiêu đề Cam) và Tối (Nền Đen, Tiêu đề Xanh biển) theo yêu cầu đề thi. Tập trung toàn bộ cấu hình màu sắc, AppBarTheme, FloatingActionButtonTheme vào một nơi, tránh hardcode màu rải rác trong UI.
lib/services/theme_service.dart Lưu trữ và đọc cờ trạng thái theme is_dark_mode bền vững qua SharedPreferences. Giúp ứng dụng ghi nhớ lựa chọn giao diện sáng/tối của người dùng kể cả sau khi đóng hoặc mở lại ứng dụng.
lib/providers/theme_provider.dart ThemeNotifier quản lý trạng thái ThemeMode hiện tại bằng Riverpod (@riverpod). Cung cấp hàm toggleTheme() giúp chuyển đổi tức thì giao diện toàn ứng dụng mà không cần restart.
lib/widgets/app_drawer.dart Thanh menu trượt bên hông (Drawer): Hiển thị avatar, tên người dùng đăng nhập hiện tại, Switch đổi theme và nút Đăng xuất. Tái sử dụng cho mọi màn hình qua thuộc tính drawer: const AppDrawer() trong Scaffold.
lib/widgets/
(item_list_widget.dart, item_grid_widget.dart, item_list_card_widget.dart, item_grid_card_widget.dart, delete_dialog.dart)		 Các thành phần UI nhỏ dùng chung: danh sách ListView, GridView responsive, các thẻ Card hiển thị và dialog xác nhận xóa. 5. Toàn Bộ Mã Nguồn File main.dart Chuẩn Khởi Động Dự Án

File lib/main.dart đảm nhiệm việc khởi tạo Flutter Engine, kiểm tra phiên đăng nhập và bọc Riverpod ProviderScope:

import 'package:flutter/material.dart';
import 'package:flutter_riverpod/flutter_riverpod.dart';
import 'screens/register_screen.dart';
import 'services/session_service.dart';
import 'screens/home_screen.dart';
import 'providers/theme_provider.dart';
import 'utils/app_theme.dart';

void main() async {
  // 1. BẮT BUỘC: Khởi tạo engine Flutter trước khi gọi bất kỳ hàm async nào (SQLite / SharedPreferences)
  WidgetsFlutterBinding.ensureInitialized();

  // 2. Kiểm tra cờ trạng thái đăng nhập từ Session
  final bool isLoggedIn = await SessionService.isLoggedIn();

  // 3. Khởi chạy ứng dụng bọc trong ProviderScope của Riverpod
  runApp(
    ProviderScope(
      child: MyApp(startAtHome: isLoggedIn),
    ),
  );
}

class MyApp extends ConsumerWidget {
  final bool startAtHome;
  const MyApp({super.key, required this.startAtHome});

  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final themeMode = ref.watch(themeProvider);

    return MaterialApp(
      title: 'Exam Practical App',
      debugShowCheckedModeBanner: false,
      themeMode: themeMode,
      theme: AppTheme.lightTheme,
      darkTheme: AppTheme.darkTheme,
      // Phân luồng điều hướng: Đã đăng nhập -> Home, chưa đăng nhập -> Register
      home: startAtHome ? const HomeScreen() : const RegisterScreen(),
    );
  }
}

6. Giải Thích Chi Tiết Code main.dart: Dùng Để Làm Gì, Dùng Thế Nào & Vì Sao?

1. WidgetsFlutterBinding.ensureInitialized();

  • Dùng để làm gì? Khởi tạo kết nối giữa Flutter Framework và Native Platform (Android/iOS/Web Engine).
  • Dùng thế nào? Đặt ở dòng đầu tiên của hàm main() async trước bất kỳ hàm bất đồng bộ nào.
  • Vì sao? Nếu gọi await SessionService.isLoggedIn() hoặc mở SQLite trước khi gọi runApp() mà thiếu dòng này, Flutter sẽ văng Exception ngay lập tức: "ServicesBinding.defaultBinaryMessenger was accessed before the binding was initialized".

2. final bool isLoggedIn = await SessionService.isLoggedIn();

  • Dùng để làm gì? Đọc cờ boolean từ SharedPreferences để xác định người dùng đã đăng nhập từ phiên trước hay chưa.
  • Dùng thế nào? Truyền giá trị isLoggedIn vào Constructor của MyApp(startAtHome: isLoggedIn).
  • Vì sao? Giúp phân luồng màn hình mở đầu mượt mà, tránh hiện tượng màn hình bị nhấp nháy chuyển trang sau khi mở app.

3. ProviderScope(child: ...)

  • Dùng để làm gì? Là Widget gốc (Root Widget) lưu trữ toàn bộ trạng thái State của các Providers trong thư viện Riverpod.
  • Dùng thế nào? Bọc trực tiếp bên ngoài MyApp bên trong lệnh runApp().
  • Vì sao? Bắt buộc phải có để các Widget con (ConsumerWidget như HomeScreen) có thể đọc và lắng nghe trạng thái qua ref.watch hoặc ref.read. Nếu thiếu ProviderScope, app sẽ báo lỗi crash ngay khi render.

4. home: startAtHome ? const HomeScreen() : const RegisterScreen()

  • Dùng để làm gì? Phân luồng giao diện xuất phát: Nếu đã đăng nhập (true) → Mở thẳng HomeScreen; nếu chưa (false) → Mở RegisterScreen (hoặc LoginScreen tùy theo đề bài thi chỉ định).
  • Dùng thế nào? Dùng toán tử 3 ngôi gán cho thuộc tính home: của MaterialApp.
  • Vì sao? Đáp ứng đúng 100% tiêu chí chấm điểm Session Gatekeeper trong thang điểm thi PE.

5. Quản lý Theme: themeMode, theme: AppTheme.lightTheme, darkTheme: AppTheme.darkTheme

  • Dùng để làm gì? Kết nối ThemeNotifier của Riverpod vào gốc MaterialApp để hỗ trợ 2 giao diện Sáng / Tối theo đề thi.
  • Dùng thế nào? MyApp kế thừa ConsumerWidget, lắng nghe final themeMode = ref.watch(themeProvider); và gán vào themeMode của MaterialApp.
  • Vì sao? Khi người dùng gạt Switch trong AppDrawer, toàn bộ widget trong ứng dụng sẽ đổi màu ngay lập tức theo đúng bảng màu quy định tại AppTheme. Xem chi tiết tại Mục 10: Drawer & Theme Service →

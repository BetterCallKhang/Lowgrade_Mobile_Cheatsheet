Mục 1: Danh Sách Thư Viện Cốt Lõi & Cấu Trúc Dự Án Mẫu Vào Thi Là Dùng

Tài liệu này được tối ưu hoá triệt để cho kỳ thi thực hành (PE / Practical Exam) theo tiêu chí: Người dùng đọc vào hiểu ngay thư viện đó là gì, dùng vào lúc nào, khi thi chỉ việc bấm nút Copy và dán vào dự án là chạy ngay mà không lo lỗi tương thích hay quên cú pháp.

⚡ Danh mục thao tác nhanh vào phòng thi:
  • 1. Lệnh Terminal khởi tạo & cài trọn bộ 1 dòng (Nhanh nhất)
  • 2. Bảng tra cứu: Thư viện là gì? Dùng lúc nào? Task thi nào cần?
  • 3. File pubspec.yaml chuẩn hoàn chỉnh (Copy & Dán đè)
  • 4. Cấu trúc thư mục lib/ chuẩn hoá sẵn sàng mọi dạng đề
  • 5. Lệnh tạo toàn bộ cây thư mục & file rỗng trong 1 giây
  • 6. Khung sườn main.dart chuẩn khởi động app an toàn
  • 7. Lưu ý sống còn trong phòng thi (Chống 0 điểm)

1. Lệnh Terminal Khởi Tạo Dự Án & Cài Trọn Bộ Thư Viện (Trong 1 Phút)

Vừa nhận đề bài thi, đọc tên thư mục yêu cầu ở trang 1 (ví dụ đề bắt đặt tên là se181234 hoặc sp26studentcode), mở Terminal tại thư mục chỉ định và copy dán đoạn lệnh sau:

# 1. Khởi tạo project (thay 'se181234' bằng tên đề bài yêu cầu)
flutter create se181234
cd se181234

# 2. Cài trọn bộ 6 thư viện dùng xuyên suốt bài thi (Mobile + Web testing)
flutter pub add sqflite sqflite_common_ffi sqflite_common_ffi_web shared_preferences flutter_riverpod http

# 3. Mở project trong VS Code / Android Studio
code .

2. Bảng Tra Cứu: Thư Viện Là Gì? Dùng Khi Nào?

Tên Thư Viện Là gì? Dùng khi nào trong bài thi? Task đề thi liên quan
sqflite Hệ quản trị CSDL SQLite cục bộ trên thiết bị di động (Android / iOS). Dùng khi đề thi yêu cầu lưu trữ dữ liệu offline, thực hiện thêm, sửa, xóa, đọc danh sách (CRUD) Users và Items. Task Register, Task Login, Task CRUD (Artwork/Book/Product)
sqflite_common_ffi &
sqflite_common_ffi_web		 Bộ cầu nối FFI cho phép chạy SQLite trên môi trường Web Chrome hoặc Desktop máy giám thị. Bắt buộc phải có nếu máy thi không mở được máy ảo Android (AVD) mà phải chạy trực tiếp ứng dụng trên Google Chrome. Tương thích đa nền tảng lúc chấm bài thi
shared_preferences Bộ nhớ lưu trữ dữ liệu dạng Key - Value cục bộ siêu nhẹ. Dùng khi làm chức năng ghi nhớ đăng nhập (Session): Lưu `isLoggedIn: true/false`, `userId`, `username`, kiểm tra khi app mở lên, và xoá cờ khi người dùng bấm Logout. Task Session Management (Login / Logout / Gatekeeper)
flutter_riverpod Thư viện quản lý trạng thái (State Management) hiện đại, an toàn và dễ debug bậc nhất Flutter. Dùng khi cần đồng bộ dữ liệu giữa các màn hình (ví dụ: màn Add thêm xong thì màn Home tự cập nhật ngay danh sách) hoặc quản lý trạng thái Filter, Theme. State Management, Auto Refresh List sau khi Thêm/Sửa/Xóa
http Thư viện gửi HTTP Request (GET, POST, PUT, DELETE) lên máy chủ API. Dùng khi đề bài yêu cầu fetch danh sách từ Mock API (MockAPI.io, Reqres, JSONPlaceholder) hoặc gửi JSON đăng ký / đăng nhập. Task Call REST API / Mock Data Online (nếu đề có API)

3. File pubspec.yaml Hoàn Chỉnh (Copy & Dán Đè)

Nếu bạn không muốn chạy lệnh Terminal từng cái, hãy mở trực tiếp file pubspec.yaml ở thư mục gốc của project, dán đoạn khai báo dưới đây vào phần dependencies và assets:

name: my_exam_project
description: "A cheatsheet exam project prepared for PE."
publish_to: 'none'
version: 1.0.0+1

environment:
  sdk: '>=3.0.0 <4.0.0'

dependencies:
  flutter:
    sdk: flutter

  # 1. Cơ sở dữ liệu SQLite cục bộ (Mobile)
  sqflite: ^2.4.2

  # 2. Hỗ trợ chạy SQLite trên Web (Chrome) & Desktop nếu máy thi yếu
  sqflite_common_ffi: ^2.3.4+4
  sqflite_common_ffi_web: ^0.4.5+1

  # 3. Quản lý phiên đăng nhập (Session: isLoggedIn, username, userId)
  shared_preferences: ^2.5.3

  # 4. Quản lý State toàn app (Đồng bộ dữ liệu màn hình)
  flutter_riverpod: ^2.6.1

  # 5. Gọi REST API (GET, POST JSON) nếu đề bài yêu cầu kết nối mạng
  http: ^1.3.0

  # Icon chuẩn Flutter
  cupertino_icons: ^1.0.8

dev_dependencies:
  flutter_test:
    sdk: flutter
  flutter_lints: ^5.0.0

flutter:
  uses-material-design: true

  # Cấu hình nạp ảnh banner/logo đề thi cấp sẵn trong thư mục assets/
  assets:
    - assets/
💡 Mẹo phòng thi sau khi sửa pubspec.yaml:

Sau khi dán và lưu file pubspec.yaml, mở Terminal gõ lệnh sau để tải packages về:

flutter pub get

4. Cấu Trúc Thư Mục Chuẩn Trong Thư Mục lib/ (Gọn Gàng & Dễ Chấm)

Dựa trên cấu trúc chuẩn từ Đề mẫu 1, bất kỳ đề thi PE nào cũng gồm 4 nhóm file chính: Models (khuôn dữ liệu), Database/Services (lưu trữ CSDL & Session), Screens (các màn hình giao diện) và main.dart (cổng điều hướng khởi động).

lib/
├── main.dart                      # Điểm khởi chạy app + Session Gatekeeper (kiểm tra login)
│
├── models/                        # Chứa các khuôn mẫu đối tượng (Data Models)
│   ├── user_model.dart            # Model tài khoản người dùng (id, username, password, email)
│   └── item_model.dart            # Model dữ liệu chính của đề (Artwork / Book / Student / Product)
│
├── database/                      # Tầng truy vấn CSDL SQLite
│   └── database_helper.dart       # Singleton SQLite, tạo bảng, seed data mẫu, CRUD toàn bộ
│
├── services/                      # Dịch vụ phụ trợ
│   ├── session_service.dart       # Quản lý SharedPreferences (saveSession, getSession, clearSession)
│   └── api_service.dart           # (Tùy chọn) Gọi API bằng http nếu đề yêu cầu REST API
│
└── screens/                       # Toàn bộ giao diện màn hình theo từng Task
    ├── login_screen.dart          # Task Đăng nhập (Logo + Form xác thực + Remember me)
    ├── register_screen.dart       # Task Đăng ký (Form validate, kiểm tra username duy nhất)
    ├── home_screen.dart           # Task Danh sách chính (Banner, ListView.builder, Dialog Xóa, Logout)
    ├── add_screen.dart            # Task Thêm mới / Chỉnh sửa dữ liệu (Form + Dropdown + Date)
    └── detail_screen.dart         # Task Xem chi tiết một Item (Card thông tin + Nút Back)

5. Lệnh Tạo Nhanh Toàn Bộ Cây Thư Mục & File Rỗng Trong 1 Giây

Khi ngồi vào máy thi, đừng tốn thời gian tạo từng thư mục bằng chuột. Mở Terminal ngay tại thư mục project và dán lệnh sau để sinh sẵn toàn bộ cấu trúc file:

Dành cho Windows (PowerShell):

# Tạo thư mục assets & các thư mục con trong lib
mkdir assets, lib\models, lib\database, lib\services, lib\screens -Force

# Tạo sẵn các file mã nguồn rỗng
New-Item lib\models\user_model.dart, lib\models\item_model.dart, lib\database\database_helper.dart, lib\services\session_service.dart, lib\screens\login_screen.dart, lib\screens\register_screen.dart, lib\screens\home_screen.dart, lib\screens\add_screen.dart, lib\screens\detail_screen.dart -ItemType File -Force

Dành cho Linux / macOS / Git Bash:

# 1 Dòng tạo sạch sẽ toàn bộ thư mục và file
mkdir -p assets lib/models lib/database lib/services lib/screens
touch lib/models/user_model.dart lib/models/item_model.dart lib/database/database_helper.dart lib/services/session_service.dart lib/screens/login_screen.dart lib/screens/register_screen.dart lib/screens/home_screen.dart lib/screens/add_screen.dart lib/screens/detail_screen.dart

6. Khung Sườn main.dart Chuẩn Khởi Động An Toàn

Dùng lúc nào? Ngay khi tạo dự án xong. Đoạn code này đã cấu hình sẵn WidgetsFlutterBinding.ensureInitialized() (bắt buộc khi dùng SQLite/Async trước runApp), bọc ProviderScope cho Riverpod, và có cổng phân luồng kiểm tra Session (nếu đã đăng nhập thì vào thẳng Home, chưa thì vào Login):

import 'package:flutter/material.dart';
import 'package:flutter_riverpod/flutter_riverpod.dart';
import 'services/session_service.dart';
import 'screens/home_screen.dart';
import 'screens/login_screen.dart';

void main() async {
  // 1. BẮT BUỘC: Khởi tạo engine Flutter trước khi gọi bất kỳ hàm async nào (SQLite / SharedPreferences)
  WidgetsFlutterBinding.ensureInitialized();

  // 2. Kiểm tra cờ trạng thái đăng nhập từ Session
  final bool isLoggedIn = await SessionService.isLoggedIn();

  // 3. Khởi chạy ứng dụng bọc trong ProviderScope của Riverpod
  runApp(
    ProviderScope(
      child: MyApp(startAtHome: isLoggedIn),
    ),
  );
}

class MyApp extends StatelessWidget {
  final bool startAtHome;
  const MyApp({super.key, required this.startAtHome});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Exam Practical App',
      debugShowCheckedModeBanner: false,
      theme: ThemeData(
        colorScheme: ColorScheme.fromSeed(seedColor: Colors.deepPurple),
        useMaterial3: true,
      ),
      // Phân luồng điều hướng: Đã đăng nhập -> Home, chưa đăng nhập -> Login
      home: startAtHome ? const HomeScreen() : const LoginScreen(),
    );
  }
}

7. Bốn Lưu Ý Sống Còn Trong Phòng Thi (Tránh Mất Điểm Oan)

⚠️ NHỚ KỸ TRƯỚC KHI BẮT ĐẦU VÀ TRƯỚC KHI NỘP BÀI:
  1. Không tự ý đổi tên thư mục gốc của project: Đề bài ghi tên gì thì lúc flutter create <ten_de> phải đặt chuẩn 100%. Nếu lỡ tạo sai tên, hãy tạo lại project mới chứ không đổi tên thư mục bằng Rename của Windows vì sẽ làm gãy đường dẫn Android/iOS build.
  2. Chép ảnh đề thi vào thư mục assets/: Đề thi thường đính kèm file nén chứa banner.jpg hoặc logo.png. Nhớ chép các file này vào thư mục assets/ vừa tạo ở bước 5, sau đó kiểm tra lại file pubspec.yaml đã bật dòng - assets/ chưa.
  3. Chạy thử F5 ngay từ đầu: Đừng code một mạch cả 7 tasks rồi mới bấm F5 chạy app. Hãy chạy thử khung sườn sườn rỗng này trước. Nếu app hiện màn hình Login thành công nghĩa là môi trường SDK máy thi đã ổn định.
  4. Lệnh dọn rác bắt buộc trước khi nén zip nộp: Khi giám thị thông báo còn 5 phút hết giờ, mở Terminal gõ ngay: 
    flutter clean
    Lệnh này sẽ xoá folder build/ nặng hàng trăm MB giúp file nộp chỉ còn dưới 1-2 MB, nộp lên phần mềm chấm thi EOS trong tích tắc!

Mục 12: Hướng Dẫn Chạy Cố Định Cổng Web Port & Sơ Đồ Luồng Hoạt Động Các Component

Tài liệu này giải thích cơ chế lưu trữ SQLite đặc thù trên trình duyệt Web (IndexedDB theo Origin), cung cấp lệnh Terminal chạy cố định một cổng để không bị mất dữ liệu giữa các lần test, và trực quan hóa toàn bộ luồng hoạt động giữa các Component (main, Session, DatabaseHelper, Riverpod Notifier, Screens và Widgets).

Danh mục nội dung:
  • 1. Vấn đề SQLite trên Web Browser & Lệnh chạy cố định Port (Sống còn)
  • 2. Cấu hình VS Code launch.json để bấm F5 tự chạy đúng port
  • 3. Sơ đồ kiến trúc tổng thể & sự kết nối giữa các Component
  • 4. Phân tích chi tiết 6 luồng hoạt động chính trong bài thi
  • 5. Bảng ma trận trách nhiệm từng Component (Component Responsibility)

1. Cơ Chế SQLite Trên Web Browser & Lệnh Chạy Cố Định Port (Cực Kỳ Quan Trọng)

HIỆN TƯỢNG "MẤT DỮ LIỆU BÍ ẨN" TRÊN TRÌNH DUYỆT CHROME:

Nhiều sinh viên vào phòng thi chạy lệnh flutter run -d chrome, đăng ký tài khoản thành công, thêm được 3 tác phẩm. Nhưng khi tắt app đi rồi chạy lại, toàn bộ dữ liệu vừa tạo biến mất hoàn toàn! Nguyên nhân không phải do code sai, mà là do cơ chế phân tách cổng của trình duyệt.

Bản chất cơ chế lưu trữ SQLite trên Browser (sqflite_common_ffi_web):

  • Trên điện thoại di động (Android / iOS): SQLite lưu trữ tập trung vào một file vật lý cố định trên ổ cứng (ví dụ: /data/data/com.example/databases/exam_app.db). Bất kể mở app lúc nào, hệ điều hành đều trỏ về đúng 1 file này.
  • Trên trình duyệt Web (Chrome / Edge): Trình duyệt không cho phép ứng dụng Web can thiệp trực tiếp vào file hệ thống máy tính. Thư viện sqflite_common_ffi_web sử dụng WebAssembly (Wasm) để biên dịch nhân SQLite C sang mã nhị phân chạy trên RAM, sau đó lưu các trang dữ liệu vào cơ sở dữ liệu IndexedDB của trình duyệt.
  • Quy tắc bảo mật Same-Origin Policy của trình duyệt: IndexedDB phân chia kho lưu trữ tuyệt đối theo từng Origin (gồm: Protocol + Domain + Port).
    Ví dụ: http://localhost:51234 và http://localhost:54321 là hai website hoàn toàn tách biệt, dữ liệu bên cổng này không bao giờ nhìn thấy dữ liệu bên cổng kia!
  • Nguyên nhân gây mất dữ liệu: Lệnh flutter run -d chrome mặc định sẽ tự động chọn một cổng ngẫu nhiên chưa sử dụng (lần 1 port 50201, lần 2 port 53892, lần 3 port 61240...). Mỗi lần chạy là một kho SQLite rỗng mới toanh!

LỆNH CHẠY BẮT BUỘC CỐ ĐỊNH 1 CỔNG (COPY & DÙNG TRONG SUỐT BUỔI THI):

Mở Terminal tại thư mục dự án và chạy duy nhất lệnh sau để cố định cổng 8080 (hoặc 3000):

# Chạy cố định trên Google Chrome tại cổng 8080 (Dữ liệu SQLite luôn được giữ nguyên vẹn)
flutter run -d chrome --web-port=8080

Nếu máy thi yêu cầu vô hiệu hóa chính sách bảo mật web (CORS / web security) để đọc file hình ảnh hoặc nạp dữ liệu ngoài, dùng thêm cờ sau:

flutter run -d chrome --web-port=8080 --web-browser-flag "--disable-web-security"

2. Cấu Hình VS Code launch.json Để Mỗi Lần Bấm F5 Tự Chạy Đúng Cổng 8080

Nếu bạn muốn bấm phím F5 hoặc nút Run trên VS Code mà không cần gõ lệnh Terminal mỗi lần, hãy tạo file .vscode/launch.json ở thư mục gốc của project với cấu hình chuẩn sau:

{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Exam Chrome (Port 8080)",
      "request": "launch",
      "type": "dart",
      "args": [
        "-d",
        "chrome",
        "--web-port=8080",
        "--web-browser-flag",
        "--disable-web-security"
      ]
    }
  ]
}

4. Phân Tích Chi Tiết 6 Luồng Hoạt Động (Data Flows) Trong Bài Thi

Luồng 1: Khởi động ứng dụng (Session Gatekeeper Flow)

  1. main() chạy đầu tiên, gọi WidgetsFlutterBinding.ensureInitialized() để mở kết nối nhị phân với engine.
  2. Gọi await SessionService.isLoggedIn() để kiểm tra key isLoggedIn trong SharedPreferences.
  3. Bọc ứng dụng trong ProviderScope để Riverpod sẵn sàng hoạt động.
  4. MyApp kiểm tra cờ: Nếu isLoggedIn == true → mở thẳng HomeScreen; nếu false → mở RegisterScreen hoặc LoginScreen.

Luồng 2: Đăng ký & Đăng nhập (Authentication Flow)

  1. Người dùng điền Form → AppValidator kiểm tra tính hợp lệ từng trường (độ dài, ký tự, định dạng email, khớp mật khẩu).
  2. Khi Đăng ký: Gọi DatabaseHelper.instance.isUsernameExists(). Nếu chưa trùng → gọi registerUser() chèn vào bảng users → Navigator.pushReplacement sang LoginScreen.
  3. Khi Đăng nhập: Gọi DatabaseHelper.instance.loginUser(username, password). Nếu hợp lệ → gọi SessionService.saveSession(username) → Navigator.pushReplacement sang HomeScreen.

Luồng 3: Đọc dữ liệu & Hiển thị danh sách (Read & Render Flow)

  1. HomeScreen (kế thừa ConsumerWidget) gọi ref.watch(itemProvider) để đăng ký theo dõi trạng thái.
  2. ItemNotifier.build() truy vấn DatabaseHelper.instance.getAllItems() lấy danh sách bản ghi và chuyển đổi thành List<ItemModel>.
  3. Trạng thái dữ liệu được xử lý mượt mà qua asyncItems.when(...):
    - loading: Hiện vòng xoay CircularProgressIndicator.
    - error: Hiện dòng báo lỗi đỏ.
    - data: Nếu rỗng → Hiện Empty State; nếu có dữ liệu → Render ListView.builder với từng dòng là một ItemCardWidget.

Luồng 4: Thêm mới & Cập nhật (Create / Update Flow)

  1. Người dùng bấm nút FloatingActionButton (+) → mở AddItemScreen; hoặc bấm icon Sửa (bút xanh) → mở EditItemScreen(item: item).
  2. EditItemScreen tự động nạp sẵn dữ liệu cũ vào các ô nhập trong hàm initState().
  3. Khi bấm LƯU → gọi ref.read(itemProvider.notifier).addItem() hoặc updateItem().
  4. Notifier cập nhật SQLite qua DatabaseHelper, sau đó gọi ref.invalidateSelf(); await future;.
  5. Lệnh Navigator.pop(context) đóng màn hình Form quay lại HomeScreen. Do HomeScreen đang ref.watch, giao diện lập tức tự động render lại danh sách mới mà không cần F5 hay load lại trang.

Luồng 5: Xóa phần tử & Xác nhận SnackBar (Delete Flow)

  1. Người dùng nhấn biểu tượng Xóa (thùng rác đỏ) trên ItemCardWidget.
  2. HomeScreen gọi final bool confirm = await DeleteDialog.show(context, item.title) để mở popup xác nhận.
  3. Nếu người dùng bấm HỦY → đóng dialog, không có gì xảy ra.
  4. Nếu người dùng bấm XÓA → gọi ref.read(itemProvider.notifier).deleteItem(item.id).
  5. SQLite xóa dòng theo ID, Riverpod làm mới State, và màn hình hiển thị ngay SnackBar thông báo: "Đã xóa '[Tên item]' thành công!" có nút ĐÓNG màu vàng.

Luồng 6: Đăng xuất người dùng (Logout Flow)

  1. Người dùng bấm icon Logout trên góc phải AppBar của HomeScreen.
  2. Hàm _logout() gọi await SessionService.clearSession() xóa sạch cờ đăng nhập và username trong SharedPreferences.
  3. Gọi Navigator.pushAndRemoveUntil(context, MaterialPageRoute(builder: (_) => const LoginScreen()), (route) => false) xóa sạch toàn bộ lịch sử điều hướng, đưa người dùng về LoginScreen mà không thể bấm Back quay lại.

5. Bảng Ma Trận Trách Nhiệm Từng Component (Quick Reference)

lib/main.dart Entrypoint Khởi tạo Engine, bọc ProviderScope, kiểm tra Session, định tuyến ban đầu. SessionService, HomeScreen, RegisterScreen

lib/widgets/item_grid_widget.dart

lib/screens/edit_item_screen.dart UI Screen Form chỉnh sửa điền sẵn dữ liệu, giữ nguyên ID, update Notifier. itemProvider, AppValidator, ItemModel
lib/screens/detail_screen.dart UI Screen Xem thông tin chi tiết item dạng Card lớn, nút mở EditItemScreen. ItemModel, EditItemScreen

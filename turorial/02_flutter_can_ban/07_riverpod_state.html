Mục 7. Quản Lý State Toàn Diện Với Riverpod & Code Generation

Bản chất State và State Management, giải mã câu hỏi "Riverpod là gì? Dùng thế nào? Vì sao nên dùng Riverpod?", phân tích hệ sinh thái các gói thư viện (flutter_riverpod, riverpod_annotation, build_runner, riverpod_generator), quy tắc sinh code tự động .g.dart, các bước thiết lập từ số 0, sự khác biệt sống còn giữa ref.watch vs ref.read, và hoàn thiện dự án quản lý danh sách Users qua REST API chuẩn mực.

1. Tổng Quan: State Là Gì? State Management Là Gì? Vì Sao Cần Riverpod?

1.1. State trong ứng dụng Flutter là gì?

Trong Flutter, mọi thứ bạn nhìn thấy trên màn hình đều là Widget. Tuy nhiên, giao diện không đứng yên mà liên tục biến đổi theo hành động của người dùng hoặc dữ liệu từ máy chủ (Server). Tất cả dữ liệu có khả năng thay đổi và làm giao diện vẽ lại (re-render) được gọi là State (Trạng thái).

1. Ephemeral State (Local State)

Là trạng thái cục bộ chỉ nằm trong phạm vi của duy nhất 1 Widget. Khi widget đó bị hủy (dispose), state cũng mất đi. Ví dụ: vị trí con trỏ trong ô nhập liệu TextField, trạng thái bật/tắt của một nút Switch, trang hiện tại của PageView.

→ Cách quản lý: Sử dụng StatefulWidget và gọi hàm setState() là hoàn toàn đủ.

2. App State (Global / Shared State)

Là dữ liệu cần được chia sẻ và dùng chung giữa nhiều màn hình khác nhau trong cây Widget (Widget Tree). Ví dụ: Thông tin người dùng đã đăng nhập (User Profile), Danh sách giỏ hàng (Cart), Cài đặt giao diện Dark/Light Mode, Dữ liệu đồng bộ từ API.

→ Cách quản lý: Cần một giải pháp quản lý tập trung chuyên biệt (State Management) như Riverpod.

1.2. Nỗi đau khi chỉ dùng setState() thuần của Flutter

Nếu cố gắng dùng setState() để quản lý dữ liệu dùng chung cho toàn bộ app, lập trình viên sẽ đối mặt với các vấn đề nhức nhối sau:

  • Truyền tham số bắc cầu (Prop Drilling): Nếu Màn hình A muốn truyền giỏ hàng xuống Màn hình D (nằm sâu qua B và C), bạn buộc phải khai báo biến giỏ hàng và truyền constructor qua từng tầng B → C → D dù B và C hoàn toàn không cần dùng đến biến này. Code trở nên rối rắm, khó bảo trì.
  • Lãng phí hiệu năng (Unnecessary Re-renders): Khi gọi setState() ở widget cha trên đỉnh, toàn bộ cây widget con phía dưới đều bị ép vẽ lại (rebuild), gây giật lag khung hình khi app phình to.
  • Trộn lẫn logic nghiệp vụ và giao diện (Spaghetti Code): Logic gọi API, lọc dữ liệu, validate bị nhồi nhét trực tiếp vào hàm build() của UI, vi phạm nguyên lý phân tách trách nhiệm (Separation of Concerns).

1.3. Riverpod là gì?

Định nghĩa Riverpod

Riverpod (được tạo bởi Remi Rousselet — cũng chính là tác giả của thư viện provider nổi tiếng) là một bộ giải pháp quản lý State (Reactive State Management) & tiêm phụ thuộc (Dependency Injection) hiện đại, an toàn kiểu dữ liệu (Compile-safe) và độc lập hoàn toàn với cây Widget của Flutter.

*Fun fact: Cái tên Riverpod chính là một từ đảo chữ cái (Anagram) của từ Provider.

1.4. Vì sao nên dùng Riverpod thay vì Provider, Bloc hay GetX?

Tiêu chí so sánh Provider truyền thống Riverpod (Phiên bản mới 2.x - 3.x) Lợi ích thực tế cho người mới
Phụ thuộc BuildContext Phụ thuộc chặt chẽ (Provider.of(context)). Không có context thì không đọc được state. Hoàn toàn không cần BuildContext. Có thể đọc Provider ở bất cứ đâu (trong Model, Service, hàm tiện ích bên ngoài UI). Tránh triệt để lỗi kinh điển ProviderNotFoundException khi context chưa sẵn sàng hoặc nằm ngoài cây Provider.
An toàn lúc biên dịch (Compile Safety) Dễ crash lúc chạy (Runtime Error) nếu chưa khai báo Provider ở trên đầu cây widget. Compile-safe 100%. Nếu khai báo sai cú pháp hoặc kiểu dữ liệu, trình biên dịch Dart sẽ báo đỏ ngay trong IDE lúc gõ code. Bắt lỗi ngay từ lúc code, không lo app bị văng đột ngột khi đi thi PE hay demo đồ án.
Tự động giải phóng bộ nhớ (Auto-dispose) Phải tự viết thủ công logic dispose, dễ gây memory leak nếu quên. Tự động hủy state khi không còn widget nào trên màn hình lắng nghe (autoDispose). Tiết kiệm RAM thiết bị và tránh lỗi dữ liệu cũ bị kẹt lại khi quay lại màn hình.
Kết hợp State (Combining State) Cần dùng ProxyProvider cực kỳ rườm rà và khó viết. Chỉ cần gọi ref.watch(providerKhac) ngay bên trong Provider là tự động phản ứng và đồng bộ. Tính toán dữ liệu dẫn xuất (vd: đếm tổng số users, tính tổng tiền hóa đơn) chỉ bằng 2 dòng code.
Code Generation hiện đại Không hỗ trợ, phải viết nhiều boilerplate lặp lại. Hỗ trợ @riverpod sinh code tự động, giúp code ngắn gọn, trực quan, loại bỏ cú pháp phức tạp. Giảm 60% lượng code phải gõ tay so với cú pháp Riverpod cũ.

1.5. Tam Giác Vàng: 3 Thành Phần Cốt Lõi Trong Riverpod (Nhà Cung Cấp, Nhà Thông Báo & Người Tiêu Thụ)

Để làm chủ và không bị rối khi học Riverpod, bạn chỉ cần nhớ mô hình "Nhà máy - Đại lý - Người tiêu dùng" gồm đúng 3 nhân vật chủ chốt sau:

1. Nhà Thông Báo (Notifier / StateNotifier)

Bản chất: Là "Bộ não xử lý logic" và là "Người quản kho dữ liệu".

  • Nhiệm vụ: Nắm giữ giá trị dữ liệu (state) và chứa toàn bộ hàm nghiệp vụ (như fetchUsers(), addUser(), clear()).
  • Cơ chế phát thanh: Mỗi khi dữ liệu trong kho thay đổi (thông qua lệnh gán state = dữ_liệu_mới), Nhà thông báo sẽ lập tức phát loa phát thanh cho hệ thống biết: "Dữ liệu vừa đổi rồi, ai đang cần thì cập nhật đi!"
  • Trong code mẫu: Chính là class UserNotifier kế thừa từ _$UserNotifier.
2. Nhà Cung Cấp (Provider)

Bản chất: Là "Cầu nối trung gian" hoặc "Đại lý phân phối" gắn nhãn công khai cho State.

  • Nhiệm vụ: Đóng gói "Nhà thông báo" thành một điểm truy cập toàn cục để giao diện có thể tìm thấy ở bất cứ nơi đâu mà không sợ mất dấu.
  • Điểm đặc biệt: Provider là một biến toàn cục nhưng không chứa dữ liệu độc quyền; nó chỉ là "ống ngắm" trỏ đến trạng thái lưu trong ProviderScope.
  • Trong code mẫu: Chính là biến userProvider (được generator tự sinh từ UserNotifier) hoặc totalUsersProvider.
3. Người Tiêu Thụ (Consumer / UI Widget)

Bản chất: Là "Khách hàng" - Giao diện người dùng (Widget) cần dữ liệu để hiển thị.

  • Nhiệm vụ: Lắng nghe "Nhà thông báo" thông qua "Nhà cung cấp" để vẽ giao diện (Text, ListView, GridView...).
  • Công cụ giao tiếp: Sử dụng chiếc thẻ thành viên WidgetRef ref:
    - Dùng ref.watch(userProvider) để "ngồi hóng" dữ liệu mới về.
    - Dùng ref.read(userProvider.notifier) để "đặt hàng / yêu cầu làm việc" (bấm nút gọi hàm).
  • Trong code mẫu: Các widget như ConsumerWidget, ConsumerStatefulWidget (màn hình HomeScreen).
Ví dụ đời sống thực tế để ghi nhớ ngay lập tức:

Tưởng tượng bạn đặt món ăn tại một nhà hàng:

  • Nhà thông báo (Notifier): Là Đầu bếp chính trong bếp. Đầu bếp nấu món (xử lý logic), khi món xong thì hô to "Món số 5 đã xong!" (cập nhật state).
  • Nhà cung cấp (Provider): Là Quầy phục vụ / Menu món. Bạn không được chạy xộc thẳng vào bếp ôm chảo của đầu bếp, mà bạn phải thông qua Quầy phục vụ (Provider) để biết món nào đang có sẵn.
  • Người tiêu thụ (Consumer): Là Thực khách (Bạn) ngồi tại bàn ăn (Giao diện UI). Bạn nhìn menu (ref.watch) chờ bê món ra ăn, và gọi bồi bàn khi muốn gọi thêm món mới (ref.read).

1.6. Mô hình luồng dữ liệu một chiều (Unidirectional Data Flow) của Riverpod

Dưới đây là sơ đồ minh họa cách dữ liệu di chuyển nhịp nhàng giữa 3 thành phần này:

ProviderScope (main.dart) - Vùng Chứa State Toàn Cục
Nơi đăng ký và lưu trữ thực tế của tất cả các Nhà cung cấp (Providers)
↓ ↑
1. Nhà Thông Báo (Notifier)
- Nắm giữ state
- Chứa các hàm nghiệp vụ (fetch, clear)
- Gán state = mới → Bắn thông báo
3. Người Tiêu Thụ (Consumer UI)
- ref.watch(userProvider): Lắng nghe vẽ lại UI
- ref.read(userProvider.notifier): Gọi hàm xử lý
2. Nhà Cung Cấp (Provider - vd: userProvider)
Làm chiếc cầu nối trung gian kết nối Người Tiêu Thụ với Nhà Thông Báo tương ứng.
→ Vòng tuần hoàn khép kín: Người Tiêu Thụ bấm nút → Gửi lệnh bằng ref.read → Nhà Thông Báo chạy hàm logic & đổi state → Bắn tín hiệu qua Nhà Cung Cấp → Người Tiêu Thụ tự động vẽ lại giao diện mới tức thì!

3. Quy Trình 5 Bước Nhỏ Triển Khai Riverpod Từ Con Số 0

Để người mới bắt đầu không bị bỡ ngỡ, toàn bộ quy trình từ cài đặt đến khi hiển thị dữ liệu lên màn hình được chia thành 5 bước nhỏ tuần tự sau:

1
Bước 1: Bọc ProviderScope tại điểm khởi động main.dart

Mọi ứng dụng sử dụng Riverpod đều bắt buộc phải bọc Widget gốc bên trong ProviderScope. Đây là nơi lưu giữ vùng nhớ của toàn bộ các Provider trong suốt vòng đời của app.

lib/main.dart
import 'package:flutter/material.dart';
import 'package:flutter_riverpod/flutter_riverpod.dart';
import 'package:state_management/ui/home_screen.dart';

void main() {
  // BẮT BUỘC: Bọc ProviderScope quanh MyApp
  runApp(const ProviderScope(child: MyApp()));
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return const MaterialApp(
      debugShowCheckedModeBanner: false,
      title: 'Riverpod Demo',
      home: HomeScreen(),
    );
  }
}
2
Bước 2: Chuẩn bị Model Class (Dữ liệu người dùng User)

Tạo file lib/model/user.dart đại diện cho cấu trúc 1 người dùng lấy từ API https://jsonplaceholder.typicode.com/users:

lib/model/user.dart
class User {
  final int id;
  final String name;
  final String username;
  final String email;

  const User({
    required this.id,
    required this.name,
    required this.username,
    required this.email,
  });

  // Constructor chuyển đổi dữ liệu từ Map JSON sang Object User
  factory User.fromJson(Map json) {
    return User(
      id: json['id'] as int,
      name: json['name'] as String,
      username: json['username'] as String,
      email: json['email'] as String,
    );
  }
}
3
Bước 3: Hiểu hai phong cách khai báo Provider (Thủ công vs Sinh code tự động)

Trước khi viết Notifier, bạn hãy quan sát sự khác biệt giữa hai cách viết để hiểu rõ vì sao cú pháp @riverpod lại được ưa chuộng hiện nay:

Cách 1: Khai báo thủ công (Manual - Kiểu cũ)

Phải tự tay chỉ định kiểu Generic phức tạp NotifierProvider<UserNotifier, List<User>>:

Cú pháp thủ công
class UserNotifier extends Notifier> {
  @override
  List build() => [];
}

// Rất dài dòng và dễ sai kiểu generic
final userNotifierProvider =
    NotifierProvider>(() {
  return UserNotifier();
});
Cách 2: Dùng Annotation @riverpod (Khuyên dùng)

Chỉ cần kế thừa _$TênClass và thêm @riverpod trên đầu, bộ generator sẽ tự động lo phần còn lại:

Cú pháp Code Generation
part 'user_notifier.g.dart';

@riverpod
class UserNotifier extends _$UserNotifier {
  @override
  List build() => [];
}
// Máy sẽ tự sinh biến: userProvider
Quy tắc vàng đặt tên tự động của riverpod_generator
  • Với Class Notifier: Tên Class (ví dụ UserNotifier) → Bỏ hậu tố Notifier còn User → Thêm hậu tố Provider và viết thường chữ đầu → Tên biến tự sinh ra sẽ là userProvider.
  • Ví dụ khác: ProductNotifier → sinh ra productProvider; CartNotifier → sinh ra cartProvider.
  • Với Function Provider: Tên hàm (ví dụ int totalUsers(Ref ref)) → Thêm đuôi Provider → Tên biến tự sinh ra sẽ là totalUsersProvider.
4
Bước 4: Viết File Provider & Chạy Lệnh Generate Code

Tạo file lib/providers/user_notifier.dart. Chú ý dòng khai báo part 'user_notifier.g.dart'; ở đầu file (file này sẽ được máy tự tạo ra sau khi gõ lệnh):

lib/providers/user_notifier.dart
import 'dart:convert';
import 'package:flutter_riverpod/flutter_riverpod.dart';
import 'package:http/http.dart' as http;
import 'package:riverpod_annotation/riverpod_annotation.dart';
import 'package:state_management/model/user.dart';

// BẮT BUỘC: Khai báo part liên kết với file tự sinh
part 'user_notifier.g.dart';

@riverpod
class UserNotifier extends _$UserNotifier {
  // 1. Hàm build(): Khởi tạo giá trị ban đầu cho State (Mảng rỗng)
  @override
  List build() {
    return [];
  }

  // 2. Hàm gọi API lấy danh sách người dùng và cập nhật State
  Future fetchUsers() async {
    final url = Uri.parse('https://jsonplaceholder.typicode.com/users');
    final response = await http.get(url);

    if (response.statusCode == 200) {
      final List jsonList = jsonDecode(response.body);
      final List users = jsonList.map((j) => User.fromJson(j)).toList();

      // QUAN TRỌNG: Gán thẳng giá trị mảng mới vào biến 'state'
      state = users;
    } else {
      throw Exception('Lỗi nạp dữ liệu: ${response.statusCode}');
    }
  }

  // 3. Hàm xóa sạch danh sách
  void clearUsers() {
    state = [];
  }
}

// 4. Dependent Provider (Provider phụ thuộc): Đếm số lượng User
// Hàm này theo dõi userProvider, khi danh sách thay đổi thì tổng số lượng tự động cập nhật!
@riverpod
int totalUsers(Ref ref) {
  final users = ref.watch(userProvider);
  return users.length;
}
Cảnh báo tư duy lập trình: Vì sao KHÔNG ĐƯỢC dùng state.add(u) hay state.clear()?
Trong Riverpod, state là bất biến (Immutable). Riverpod so sánh sự thay đổi trạng thái dựa trên Địa chỉ tham chiếu bộ nhớ (Object Identity). Nếu bạn gọi state.add(u), bạn chỉ sửa đổi bên trong cùng một ô nhớ của mảng cũ, địa chỉ mảng không đổi nên Riverpod sẽ hiểu lầm là dữ liệu chưa thay đổi và không kích hoạt giao diện vẽ lại. Luôn luôn gán state = mảng_mới!

Lệnh chạy sinh file .g.dart trong Terminal:

Terminal (Dự án gốc)
# Lệnh 1: Chạy sinh 1 lần và tự động ghi đè nếu có xung đột file cũ
dart run build_runner build --delete-conflicting-outputs

# Lệnh 2: Chế độ theo dõi liên tục (Tự động sinh lại mỗi khi bấm Ctrl + S lưu code)
dart run build_runner watch --delete-conflicting-outputs

Sau khi lệnh chạy hoàn tất và thông báo [INFO] Succeeded, file user_notifier.g.dart sẽ xuất hiện cùng thư mục, tất cả các gạch chân đỏ trong code sẽ hoàn toàn biến mất!

5
Bước 5: Tiêu thụ State trên giao diện UI (ConsumerWidget vs ConsumerStatefulWidget)

Để màn hình đọc được dữ liệu từ Riverpod, Flutter cung cấp 2 widget thay thế tương ứng:

  • Thay StatelessWidget bằng ConsumerWidget: Nhận thêm tham số WidgetRef ref trong hàm build(BuildContext context, WidgetRef ref).
  • Thay StatefulWidget bằng ConsumerStatefulWidget & ConsumerState<T>: Cho phép truy cập thuộc tính ref toàn cục trực tiếp ở bất kỳ đâu trong State.

Bảng so sánh cốt lõi: Khi nào dùng ref.watch, ref.read, và ref.listen?

Cú pháp lệnh Vị trí được phép sử dụng Cơ chế hoạt động Trường hợp thực tế
ref.watch(provider) Bên trong hàm build() của Widget Lắng nghe liên tục. Mỗi khi state đổi giá trị, widget hiện tại sẽ tự động chạy lại hàm build để cập nhật giao diện mới nhất. Lấy danh sách người dùng để render ListView, lấy trạng thái DarkMode, hiển thị số dư giỏ hàng.
ref.read(provider.notifier) Bên trong các hàm xử lý sự kiện (onPressed, onTap...) Lấy đối tượng xử lý một lần duy nhất mà không đăng ký lắng nghe vẽ lại. Bấm nút Fetch dữ liệu (.fetchUsers()), bấm nút Xóa danh sách (.clearUsers()), bấm nút Đăng xuất.
ref.read(provider) Bên trong hàm sự kiện hoặc phương thức Notifier Chỉ đọc trích xuất giá trị state tại đúng thời điểm đó mà không quan tâm các thay đổi tương lai. Kiểm tra điều kiện nhanh trước khi chuyển trang (ví dụ: if (ref.read(authProvider) == null)).
ref.listen(provider, (prev, next) {}) Bên trong hàm build() Lắng nghe sự kiện để thực thi một hành động phụ (Side-effect) thay vì vẽ lại giao diện. Bắn thông báo SnackBar, bật AlertDialog báo lỗi mạng, hoặc điều hướng chuyển trang.

4. Toàn Bộ Mã Nguồn Màn Hình Giao Diện Hoàn Chỉnh (home_screen.dart)

File giao diện thực chiến hoàn chỉnh sử dụng ConsumerStatefulWidget, bao gồm các nút bấm hành động (Fetch, Clear), hiển thị số lượng người dùng từ Dependent Provider, và kết hợp bố cục GridView 4 cột trực quan:

lib/ui/home_screen.dart
import 'package:flutter/material.dart';
import 'package:flutter_riverpod/flutter_riverpod.dart';
import 'package:state_management/model/user.dart';
import 'package:state_management/providers/user_notifier.dart';

// ===============================================================
// CÁCH 1: DÙNG ConsumerStatefulWidget (Tiện khi cần initState, dispose)
// ===============================================================
class HomeScreen extends ConsumerStatefulWidget {
  const HomeScreen({super.key});

  @override
  ConsumerState createState() => _HomeScreenState();
}

class _HomeScreenState extends ConsumerState {
  @override
  Widget build(BuildContext context) {
    // 1. Dùng ref.watch() để lắng nghe danh sách users từ Riverpod
    final List users = ref.watch(userProvider);

    // 2. Dùng ref.watch() để theo dõi tổng số lượng từ dependent provider
    final int totalCount = ref.watch(totalUsersProvider);

    return Scaffold(
      appBar: AppBar(
        title: const Text('Danh sách người dùng (Riverpod)'),
        backgroundColor: Colors.teal,
        foregroundColor: Colors.white,
      ),
      body: Padding(
        padding: const EdgeInsets.all(12.0),
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.stretch,
          children: [
            // Hàng nút bấm kích hoạt hành động
            Row(
              children: [
                Expanded(
                  child: ElevatedButton.icon(
                    style: ElevatedButton.styleFrom(
                      backgroundColor: Colors.teal,
                      foregroundColor: Colors.white,
                    ),
                    onPressed: () {
                      // Dùng ref.read(provider.notifier) để gọi phương thức nghiệp vụ
                      ref.read(userProvider.notifier).fetchUsers();
                    },
                    icon: const Icon(Icons.cloud_download),
                    label: const Text('Fetch Users'),
                  ),
                ),
                const SizedBox(width: 10),
                Expanded(
                  child: ElevatedButton.icon(
                    style: ElevatedButton.styleFrom(
                      backgroundColor: Colors.redAccent,
                      foregroundColor: Colors.white,
                    ),
                    onPressed: () {
                      // Xóa dữ liệu
                      ref.read(userProvider.notifier).clearUsers();
                    },
                    icon: const Icon(Icons.delete_outline),
                    label: const Text('Clear All'),
                  ),
                ),
              ],
            ),
            const SizedBox(height: 12),

            // Hiển thị tổng số lượng người dùng
            Container(
              padding: const EdgeInsets.symmetric(vertical: 8, horizontal: 12),
              decoration: BoxDecoration(
                color: Colors.teal.withOpacity(0.1),
                borderRadius: BorderRadius.circular(8),
                border: Border.all(color: Colors.teal.withOpacity(0.3)),
              ),
              child: Text(
                'Tổng số người dùng hiện có: $totalCount',
                style: const TextStyle(
                  fontSize: 16,
                  fontWeight: FontWeight.bold,
                  color: Colors.teal,
                ),
                textAlign: TextAlign.center,
              ),
            ),
            const SizedBox(height: 12),

            // Hiển thị danh sách thẻ người dùng dạng GridView
            Expanded(
              child: users.isEmpty
                  ? const Center(
                      child: Text(
                        'Chưa có dữ liệu. Bấm "Fetch Users" để tải!',
                        style: TextStyle(color: Colors.grey, fontSize: 15),
                      ),
                    )
                  : GridView.count(
                      crossAxisCount: 2, // 2 cột trên điện thoại
                      crossAxisSpacing: 10,
                      mainAxisSpacing: 10,
                      childAspectRatio: 1.4,
                      children: users.map((u) {
                        return Card(
                          elevation: 3,
                          shape: RoundedRectangleBorder(
                            borderRadius: BorderRadius.circular(10),
                          ),
                          child: Padding(
                            padding: const EdgeInsets.all(10.0),
                            child: Column(
                              crossAxisAlignment: CrossAxisAlignment.start,
                              mainAxisAlignment: MainAxisAlignment.center,
                              children: [
                                Row(
                                  children: [
                                    CircleAvatar(
                                      radius: 16,
                                      backgroundColor: Colors.teal.shade100,
                                      child: Text(
                                        u.id.toString(),
                                        style: const TextStyle(
                                          fontWeight: FontWeight.bold,
                                          color: Colors.teal,
                                        ),
                                      ),
                                    ),
                                    const SizedBox(width: 8),
                                    Expanded(
                                      child: Text(
                                        u.username,
                                        style: const TextStyle(
                                          fontWeight: FontWeight.bold,
                                          fontSize: 14,
                                        ),
                                        overflow: TextOverflow.ellipsis,
                                      ),
                                    ),
                                  ],
                                ),
                                const Divider(height: 16),
                                Text(
                                  u.name,
                                  style: const TextStyle(fontSize: 13),
                                  overflow: TextOverflow.ellipsis,
                                ),
                                const SizedBox(height: 2),
                                Text(
                                  u.email,
                                  style: const TextStyle(
                                    fontSize: 11.5,
                                    color: Colors.grey,
                                  ),
                                  overflow: TextOverflow.ellipsis,
                                ),
                              ],
                            ),
                          ),
                        );
                      }).toList(),
                    ),
            ),
          ],
        ),
      ),
    );
  }
}

// CÁCH 2: DÙNG ConsumerWidget (Gọn gàng nhất khi không cần lifecycle)
// ===============================================================
class SimpleUserScreen extends ConsumerWidget {
  const SimpleUserScreen({super.key});

  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final users = ref.watch(userProvider);

    return Scaffold(
      appBar: AppBar(title: const Text('Simple ConsumerWidget')),
      body: ListView.builder(
        itemCount: users.length,
        itemBuilder: (context, index) {
          final u = users[index];
          return ListTile(
            leading: const Icon(Icons.person, color: Colors.teal),
            title: Text('${u.name} (@${u.username})'),
            subtitle: Text(u.email),
            trailing: Text('#${u.id}'),
          );
        },
      ),
    );
  }
}

5. Bảng Tổng Hợp Các Lỗi Thường Gặp & Cách Khắc Phục Tức Thì

Hiện tượng lỗi Nguyên nhân gốc rễ Cách xử lý chuẩn xác
No ProviderScope found khi vừa chạy app Quên bọc ProviderScope quanh MyApp() trong hàm main(). Vào main.dart, sửa thành runApp(const ProviderScope(child: MyApp()));.
Gạch đỏ ở _$UserNotifier hoặc file .g.dart báo không tìm thấy Chưa chạy bộ công cụ build_runner để sinh code tự động. Mở Terminal chạy lệnh: dart run build_runner build --delete-conflicting-outputs.
Giao diện không cập nhật sau khi thêm phần tử vào danh sách Dùng state.add(item) thay vì tạo mảng mới. Sửa thành: state = [...state, item]; để tạo bản sao tham chiếu mới kích hoạt render.
Gặp lỗi lặp vô hạn (Infinite Re-render loop) Gọi ref.read() hoặc các hàm làm đổi state trực tiếp ngay giữa lòng hàm build(). Chỉ đặt các lệnh thay đổi state bên trong các callback sự kiện như onPressed hoặc dùng ref.listen.

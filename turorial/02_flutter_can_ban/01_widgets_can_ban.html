1. Widget trong Flutter là gì? "Everything is a Widget"

Định nghĩa cốt lõi

Trong Flutter, Widget là khối xây dựng cơ bản (building block) của giao diện người dùng. Khác với lập trình Android gốc (viết XML) hay Web (viết HTML/CSS riêng, JavaScript riêng), Flutter gom toàn bộ giao diện, bố cục căn chỉnh (Layout), màu sắc, phông chữ và cả hiệu ứng tương tác thành các lớp đối tượng Dart gọi là Widget.

Câu nói nổi tiếng của đội ngũ phát triển Flutter: "Everything in Flutter is a Widget" (Mọi thứ đều là Widget):

Loại Widget Ví dụ tiêu biểu Nhiệm vụ & Chức năng
Widget hiển thị nội dung (Visual) Text, Image, Icon, CircleAvatar Vẽ các thành phần mắt nhìn thấy được: chữ, hình chụp, biểu tượng.
Widget bố cục & căn chỉnh (Layout) Row, Column, Stack, Center, Padding, SizedBox Sắp xếp vị trí các widget con: nằm ngang, nằm dọc, đè lên nhau, tạo khoảng cách đệm.
Widget tương tác (Interactive/Input) ElevatedButton, TextField, Checkbox, Switch, Slider Lắng nghe thao tác người dùng: bấm, gõ phím, bật/tắt, kéo thanh trượt.
Widget cấu trúc & điều hướng (Structure) MaterialApp, Scaffold, AppBar, BottomNavigationBar Cung cấp bộ khung chuẩn Material Design của Google cho ứng dụng.

2. Giải mã Bộ Ba Cây: Widget Tree → Element Tree → Render Tree

Tại sao Flutter lại đạt được tốc độ mượt mà 60fps - 120fps? Bí mật nằm ở kiến trúc 3 tầng cây rendering bên dưới:

1. Widget Tree (Bản thiết kế - Blueprint)

Là cây code do chính bạn viết ra. Widget có tính chất Immutable (bất biến - không thể thay đổi giá trị một khi đã tạo). Mỗi khi màn hình cập nhật, widget cũ bị vứt đi và tạo mới lại siêu nhanh (rẻ về mặt bộ nhớ và CPU).

Text('Xin chào', style: TextStyle(...))

2. Element Tree (Bộ điều phối - Manager)

Là cầu nối sống giữa Widget và RenderObject. Element giữ trạng thái thực tế và vòng đời (Lifecycle). Nó so sánh (diffing) widget cũ và widget mới: nếu kiểu class và Key không đổi, nó chỉ cập nhật thuộc tính mà không tạo lại RenderObject.

3. Render Tree (Thợ vẽ - Painter)

Là cây chứa các RenderObject. Đây là tầng trực tiếp tính toán tọa độ (kích thước width, height), đo lường ràng buộc layout và gọi hàm vẽ đồ họa lên màn hình (Canvas). Tầng này rất tốn tài nguyên, nên Flutter luôn tái sử dụng tối đa.

Quy trình làm việc khi bạn bấm nút thay đổi giao diện (Hot Reload hoặc setState)
  1. Bạn gọi setState(), hàm build() chạy lại và tạo ra một Widget Tree mới.
  2. Element Tree kiểm tra: "Widget mới này có cùng Runtime Type và Key với Widget trước không?"
  3. Nếu cùng loại: Element giữ nguyên đối tượng RenderObject cũ, chỉ bảo nó: "Cập nhật lại chuỗi text thành chuỗi mới đi!".
  4. Nhờ đó, Flutter không cần phải huỷ toàn bộ UI đi vẽ lại từ đầu → Hiệu năng đạt 60fps cực kỳ nhẹ nhàng!

3. Phân biệt StatelessWidget và StatefulWidget & Vòng đời State Lifecycle

Khi tạo bất kỳ màn hình hoặc component nào trong Flutter, quyết định đầu tiên là chọn Stateless hay Stateful.

StatelessWidget (Giao diện Tĩnh)

Bản chất: Màn hình hoặc widget chỉ hiển thị dữ liệu tĩnh được truyền vào từ bên ngoài qua Constructor. Bản thân nó không có dữ liệu nội tại tự biến đổi theo thời gian.

Ví dụ: Nhãn chữ Text, icon Icon(Icons.star), màn hình tĩnh Giới thiệu ứng dụng (About Screen).

Phím tắt tạo nhanh trong Android Studio: Gõ stless rồi bấm phím Tab hoặc Enter.

StatelessWidget mẫu
import 'package:flutter/material.dart';

class MyHeader extends StatelessWidget {
  final String title;
  const MyHeader({super.key, required this.title});

  @override
  Widget build(BuildContext context) {
    return Container(
      padding: const EdgeInsets.all(16),
      color: Colors.blueAccent,
      child: Text(
        title,
        style: const TextStyle(color: Colors.white, fontSize: 18),
      ),
    );
  }
}
StatefulWidget (Giao diện Động)

Bản chất: Widget có dữ liệu nội tại (gọi là State) có thể thay đổi sau khi người dùng bấm nút, nhập form, gạt switch hoặc nhận phản hồi từ API.

Ví dụ: Form đăng nhập (chứa ô nhập text và nút bấm), bộ đếm số lượt thích, danh sách tải thêm trang.

Phím tắt tạo nhanh: Gõ stful rồi bấm Tab hoặc Enter.

StatefulWidget gồm 2 class
import 'package:flutter/material.dart';

// Class 1: Khai báo Widget (Immutable)
class CounterScreen extends StatefulWidget {
  const CounterScreen({super.key});

  @override
  State createState() => _CounterScreenState();
}

// Class 2: Lưu giữ State & Xử lý Logic (Mutable)
class _CounterScreenState extends State {
  int _counter = 0;

  void _increment() {
    setState(() {
      _counter++; // Thay đổi giá trị và báo Flutter vẽ lại
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: Center(child: Text('Số lần bấm: $_counter')),
      floatingActionButton: FloatingActionButton(
        onPressed: _increment,
        child: const Icon(Icons.add),
      ),
    );
  }
}

Vòng đời chi tiết của StatefulWidget (State Lifecycle)

Một StatefulWidget trải qua các giai đoạn từ lúc sinh ra trên màn hình cho tới khi bị huỷ khỏi bộ nhớ. Hiểu rõ từng giai đoạn giúp bạn tránh lỗi rò rỉ bộ nhớ (memory leak) hoặc gọi API sai thời điểm:

1. createState()
Khởi tạo đối tượng State

Được gọi ngay khi StatefulWidget được gắn vào cây widget. Trả về instance của class State<T>.

2. initState()
Chạy 1 lần duy nhất khi State được sinh ra

Nơi lý tưởng để: khởi tạo biến, đăng ký lắng nghe controller (TextEditingController, ScrollController, AnimationController), hoặc kích hoạt hàm gọi API lần đầu tiên.

Quy tắc: Bắt buộc phải gọi super.initState() ngay dòng đầu tiên.

3. didChangeDependencies()
Chạy sau initState() hoặc khi dữ liệu kế thừa thay đổi

Được gọi khi các đối tượng mà widget phụ thuộc (như InheritedWidget, Theme.of(context), MediaQuery.of(context)) có sự thay đổi giá trị.

4. build()
Xây dựng và vẽ giao diện UI (Chạy nhiều lần)

Hàm quan trọng nhất, trả về cây widget sẽ hiển thị. Hàm này sẽ được tự động gọi lại mỗi khi bạn kích hoạt setState().

Lưu ý vàng: Không bao giờ gọi hàm bất đồng bộ async hoặc gọi API trực tiếp trong build() vì sẽ khiến app gọi API liên tục vô tận!

5. didUpdateWidget()
Khi Widget cha build lại và truyền thông số mới

Được gọi khi widget cha cấu hình lại và muốn truyền các thuộc tính (props) mới vào widget hiện tại.

6. deactivate()
Tạm thời tháo gỡ khỏi Element Tree

Xảy ra khi State bị gỡ khỏi cây widget, nhưng vẫn có khả năng được tái sử dụng lại ở vị trí khác trước khi frame kết thúc.

7. dispose()
Huỷ vĩnh viễn đối tượng State khỏi bộ nhớ

Được gọi khi màn hình bị đóng lại (Pop màn hình, chuyển trang vĩnh viễn). Đây là nơi bắt buộc phải giải phóng tài nguyên:

@override
void dispose() {
  myController.dispose(); // Giải phóng controller tránh leak RAM
  streamSubscription.cancel(); // Huỷ đăng ký Stream
  super.dispose(); // Gọi hàm cha ở dòng cuối cùng
}

4. Giải phẫu Bộ Khung Gốc: MaterialApp và Scaffold Anatomy

4.1. MaterialApp - Bộ não định hình toàn bộ ứng dụng

Nó là gì và nằm ở đâu? MaterialApp là widget bọc ngoài cùng của toàn bộ ứng dụng Flutter, thường nằm trong hàm runApp() tại file main.dart. Nó thiết lập phong cách thiết kế Material Design, quản lý hệ thống phân trang định tuyến (Navigation/Routes), và áp dụng bộ màu sắc (ThemeData).

5. Định nghĩa State và Cơ chế setState() Hoạt Động Ra Sao?

State là gì?

State là bất kỳ thông tin hay dữ liệu nào trong ứng dụng mà có thể thay đổi theo thời gian và cần được phản ánh trực quan lên màn hình giao diện. Ví dụ: nội dung người dùng gõ vào ô tìm kiếm, trạng thái tick chọn checkbox, số lượng sản phẩm trong giỏ hàng, hoặc danh sách người dùng tải về từ server.

setState() là gì và vì sao bắt buộc phải dùng?

Nếu bạn chỉ thay đổi một biến: counter = counter + 1; mà không bọc trong setState(), thì giá trị của biến trong RAM máy tính thực sự đã tăng, nhưng màn hình điện thoại vẫn hiển thị con số cũ! Bởi vì hệ thống Flutter không hề biết rằng dữ liệu vừa bị thay đổi.

Khi bạn gọi setState(() { counter++; }), bạn đang gửi một tín hiệu thông báo cho Flutter: "Nội bộ State đã thay đổi rồi, hãy đánh dấu widget này là 'dirty' và gọi lại hàm build() để vẽ lại màn hình với dữ liệu mới ngay đi!"

Cách làm SAI (UI không bao giờ cập nhật)
void _onButtonPressed() {
  _isFavorited = true; // Biến đổi trong RAM nhưng UI đóng băng!
}
Cách làm ĐÚNG CHUẨN
void _onButtonPressed() {
  setState(() {
    _isFavorited = !_isFavorited; // Flutter lập tức vẽ lại giao diện
  });
}
3 Lưu ý quan trọng khi dùng setState():
  • Chỉ có thể gọi setState() bên trong class State của một StatefulWidget (StatelessWidget không có hàm này).
  • Không để các tác vụ nặng (như gọi API bằng http.get hoặc đọc file ghi đĩa) bên trong hàm callback của setState(). Hãy đợi lấy được dữ liệu xong rồi mới gọi setState() để gán vào biến.
  • Nếu widget đã bị tháo khỏi màn hình (unmounted) mà gọi setState() sẽ gây crash. Luôn kiểm tra if (mounted) setState(...) khi làm việc với hàm bất đồng bộ async.

6. Hiển Thị Danh Sách Cuộn: ListView, Card, ListTile & Chèn Hình Ảnh

💡 Giải đáp cốt lõi: ListView và GridView có các Constructor đặc biệt không? Tham số của chúng khác nhau ra sao?

CÂU TRẢ LỜI LÀ: CÓ! Cả hai đều sở hữu các Constructor đặt tên đặc biệt (như .builder, .separated, .count, .extent).

  • Điểm GIỐNG NHAU: Các tham số điều khiển cuộn (padding, physics, reverse, shrinkWrap, controller, scrollDirection) hoàn toàn như nhau ở mọi constructor.
  • Điểm KHÁC NHAU: Khác biệt ở cách nhận dữ liệu: Constructor mặc định bắt buộc dùng mảng children: [...] (tốn RAM vì dựng hết một lúc), còn Constructor .builder dùng itemCount + itemBuilder (tiết kiệm RAM theo cơ chế Lazy Loading chỉ render những gì nhìn thấy trên màn hình).

Khi danh sách phần tử vượt quá chiều cao màn hình điện thoại, nếu dùng Column sẽ lập tức dính lỗi sọc vàng-đen (A RenderFlex overflowed by ... pixels). Giải pháp cứu cánh chính là ListView.

6.1. Bản Chất Các Constructor của ListView: Tham Số Giống & Khác Nhau Ra Sao?

Câu trả lời cốt lõi

CÓ! Cả ListView và GridView đều có các Constructor đặt tên (Named Constructors) đặc biệt phục vụ từng mục đích và bài toán tối ưu bộ nhớ khác nhau. Về cơ bản: Các tham số điều khiển cuộn chung (như padding, physics, reverse, shrinkWrap, controller) thì HOÀN TOÀN GIỐNG NHAU giữa mọi constructor. Điểm khác biệt chí mạng nằm ở CÁCH NÓ NHẬN DỮ LIỆU CON (Data Source):

• scrollDirection
• reverse

7.1. Bảng Chi Tiết Toàn Bộ Thuộc Tính & Tham Số của GridView

Tên Tham Số Kiểu Dữ Liệu Ý nghĩa & Hướng Dẫn Sử Dụng Chi Tiết
gridDelegate SliverGridDelegate Cốt lõi của GridView: Quyết định cách bố trí chia cột, gồm 2 loại:
• SliverGridDelegateWithFixedCrossAxisCount: Cố định số cột (ví dụ 2 cột).
• SliverGridDelegateWithMaxCrossAxisExtent: Tự động chia cột theo kích thước màn hình.
crossAxisCount int Số lượng cột hiển thị trên màn hình (dùng trong GridView.count hoặc delegate fixed count). Thường là 2 hoặc 3 cột trên Mobile.
crossAxisSpacing double Khoảng cách khoảng hở theo chiều ngang giữa 2 cột kề nhau (ví dụ: 10px).
mainAxisSpacing double Khoảng cách khoảng hở theo chiều dọc giữa hàng trên và hàng dưới (ví dụ: 10px).
childAspectRatio double Tỉ lệ giữa (Chiều Rộng / Chiều Cao) của mỗi ô con.
• Mặc định = 1.0 (Ô vuông vức).
• Nếu ô chứa hình ảnh + 2 dòng chữ bên dưới → nên đặt từ 0.7 đến 0.8 để ô có đủ chiều cao chứa chữ mà không bị lỗi tràn pixel.
itemCount int? Tổng số lượng ô cần hiển thị trong GridView.builder.
itemBuilder Widget Function(BuildContext, int) Hàm sinh ra widget của từng ô thứ index (Lazy render tối ưu bộ nhớ).
padding EdgeInsetsGeometry? Lề thụt vào của toàn bộ lưới so với cạnh màn hình thiết bị.
physics & shrinkWrap ScrollPhysics? & bool Tương tự như ListView: dùng để khoá cuộn hoặc co giãn vừa vặn kích thước nội dung.

7.2. Bản Chất Các Constructor của GridView: Tham Số Khác Nhau Thế Nào?

Giống như ListView, toàn bộ các tham số cuộn (padding, physics, shrinkWrap, reverse) là giống nhau. Sự khác biệt chỉ nằm ở 2 yếu tố: "Dữ liệu tĩnh hay động?" và "Chia cột theo số lượng cố định hay theo độ rộng pixel?":

• children: List<Widget> (Mảng widget dựng sẵn)

value double Giá trị hiện tại của con trượt (bắt buộc phải nằm giữa min và max).
min và max double Giới hạn nhỏ nhất (mặc định 0.0) và lớn nhất (mặc định 1.0).
divisions int? Số nấc chia rời rạc: nếu đặt 10 thì con trượt sẽ nhảy theo từng khấc 10%.
label String? Bong bóng hiển thị giá trị số nổi lên trên con trượt khi ngón tay đang đè kéo.
onChanged ValueChanged<double>? Callback trả về giá trị số thực mới để cập nhật qua setState().
Ví dụ Slider điều chỉnh âm lượng
double _volume = 65.0;

Column(
  children: [
    Text('Âm lượng: ${_volume.round()}%'),
    Slider(
      value: _volume,
      min: 0,
      max: 100,
      divisions: 20, // Chia làm 20 nấc (mỗi nấc 5%)
      label: '${_volume.round()}%',
      activeColor: Colors.deepPurpleAccent,
      onChanged: (double val) {
        setState(() {
          _volume = val;
        });
      },
    ),
  ],
)

Tổng Kết & Sơ Đồ Tư Duy Ghi Nhớ

Tóm tắt các điểm bắt buộc phải nhớ
  • Mọi thành phần nhìn thấy trên màn hình đều là Widget.
  • Widget Tree là bản thiết kế tạm thời; Element Tree quản lý vòng đời; Render Tree thực hiện tính toán và vẽ đồ họa.
  • Chỉ dùng StatefulWidget khi có dữ liệu nội bộ tự thay đổi qua setState().
  • Gốc của ứng dụng luôn là MaterialApp; Khung của từng trang màn hình luôn là Scaffold.
  • Luôn giải phóng controller trong hàm dispose() của State để tránh rò rỉ bộ nhớ.
  • Khi hiển thị danh sách dài: ưu tiên tuyệt đối dùng ListView.builder và GridView.builder để ứng dụng mượt mà không tốn RAM.

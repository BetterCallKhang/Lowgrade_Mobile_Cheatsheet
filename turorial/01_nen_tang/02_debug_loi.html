Phần 2. Debug và lỗi thường gặp

Cách đọc thông báo lỗi, các công cụ debug trong Android Studio, và bảng tra cứu lỗi chia làm 2 nhóm: lỗi code và lỗi nền tảng. Cách chạy app, Run/Debug, Hot Reload/Hot Restart xem ở Phần 1, mục 6.

1. Phân loại lỗi và cách đọc thông báo lỗi

Khái niệm

Lỗi code là lỗi do code Dart / Flutter bạn viết: sai cú pháp, sai kiểu dữ liệu, dùng biến null, đặt Widget sai chỗ. Sửa bằng cách sửa code trong lib/.

Lỗi nền tảng là lỗi do môi trường và công cụ: cài SDK, PATH, Android Studio, emulator, tải thư viện, Gradle, build native. Code có thể đúng hoàn toàn nhưng app vẫn không chạy được. Sửa bằng cách cài đặt, cấu hình, chạy lệnh.

Lỗi code chia làm 3 loại theo thời điểm xuất hiện

LoạiXuất hiện khi nàoNhận biết
Lỗi biên dịch (compile error) Ngay khi đang gõ code, trước khi chạy. Gạch đỏ dưới code, app không chạy được. Danh sách đầy đủ ở cửa sổ Dart Analysis.
Lỗi khi chạy (runtime error / exception) App đã chạy, lỗi xảy ra khi tới đoạn code có vấn đề. Ở chế độ debug: màn hình đỏ chữ vàng trên app, thông báo lỗi in ra cửa sổ Run / Debug.
Lỗi giao diện (layout error) Khi Flutter vẽ màn hình. Là một dạng lỗi khi chạy. Vạch sọc vàng đen, màn hình trắng hoặc đỏ, cửa sổ Run in khung EXCEPTION CAUGHT BY RENDERING LIBRARY.
Gạch vàng và gạch xám không phải lỗi

Gạch vàng là cảnh báo (warning), gạch xám là gợi ý (hint, ví dụ biến không dùng tới). App vẫn chạy bình thường, nên sửa để code sạch.

Cách đọc thông báo lỗi khi chạy

Thông báo lỗi trong cửa sổ Run thường gồm 2 phần: tên lỗi + mô tả ở trên, và stack trace ở dưới.

Khái niệm

Stack trace là danh sách các hàm đang được gọi lồng nhau tại thời điểm xảy ra lỗi, dòng trên cùng là nơi lỗi xảy ra. Mỗi dòng có tên file, số dòng và số cột.

Ví dụ thông báo lỗi trong cửa sổ Run
======== Exception caught by widgets library ========
The following _TypeError was thrown building NoteListScreen:
Null check operator used on a null value          # Tên lỗi: đọc dòng này trước

#0      _NoteListScreenState.build (package:ten_project/ui/note_list_screen.dart:25:30)   # Code của bạn: file, dòng 25, cột 30
#1      StatefulElement.build (package:flutter/src/widgets/framework.dart:5729:27)       # Code của Flutter: bỏ qua
...
  1. Đọc dòng tên lỗi để biết lỗi gì, tra ở bảng mục 5.
  2. Tìm dòng đầu tiên trong stack trace có package:ten_project/ (tên project của bạn). Đó là chỗ trong code của bạn gây lỗi.
  3. Bấm vào đường dẫn màu xanh trong cửa sổ Run để Android Studio nhảy thẳng tới dòng đó.
  4. Các dòng package:flutter/... là code bên trong Flutter, thường không cần đọc.

2. Debug bằng Breakpoint

Khái niệm

Breakpoint là điểm dừng đặt tại một dòng code. Khi chạy ở chế độ Debug, app sẽ tạm dừng ngay trước khi thực thi dòng đó, cho phép xem giá trị các biến tại thời điểm đó.

1
Đặt breakpoint

Bấm vào lề trái cạnh số dòng, xuất hiện chấm đỏ. Hoặc đặt con trỏ ở dòng đó nhấn Ctrl + F8 (Mac: Cmd + F8). Bấm lại để bỏ.

2
Chạy Debug

Bấm nút Debug (Shift + F9, Mac: Ctrl + D). Bấm Run thì breakpoint không có tác dụng. Thao tác trên app để code chạy tới dòng có breakpoint. Dòng đó được tô xanh, cửa sổ Debug mở ra ở dưới.

3
Xem biến và đi từng bước

Tab Variables hiển thị giá trị các biến hiện tại. Dùng các nút sau để điều khiển:

NútTác dụngWin/LinuxMac
Step OverChạy dòng hiện tại, sang dòng kế tiếp. Không đi vào bên trong hàm được gọi.F8F8
Step IntoĐi vào bên trong hàm được gọi ở dòng hiện tại.F7F7
Step OutChạy hết hàm hiện tại, quay về chỗ gọi nó.Shift + F8Shift + F8
ResumeChạy tiếp cho tới breakpoint kế tiếp.F9Cmd + Option + R
Evaluate ExpressionGõ một biểu thức bất kỳ để tính giá trị ngay lúc đang dừng, ví dụ list.length.Alt + F8Option + F8

3. Debug bằng in log

Cách nhanh để kiểm tra code có chạy tới đâu và biến có giá trị gì. Kết quả hiện ở cửa sổ Run (hoặc Debug) phía dưới Android Studio.

dart
import 'package:flutter/foundation.dart';

void loadData() {
  final list = ['a', 'b'];

  print('So phan tu: ${list.length}');      // In ra console. Lint sẽ cảnh báo avoid_print
  debugPrint('Danh sach: $list');         // Nên dùng: không bị cắt chữ khi log quá dài
}
Vì sao print bị gạch dưới màu vàng

Bộ lint flutter_lints có luật avoid_print, nhắc rằng print không nên để lại trong app thật. Đây là cảnh báo, không phải lỗi, app vẫn chạy. Dùng debugPrint để hết cảnh báo.

4. Flutter Inspector

Khái niệm

Flutter Inspector là công cụ xem cây Widget của màn hình đang chạy. Bấm vào một Widget trên cây sẽ thấy kích thước, padding, thuộc tính của nó. Rất hữu ích khi giao diện bị lệch, tràn mà không biết do Widget nào.

  1. Chạy app (Run hoặc Debug).
  2. Mở cửa sổ Flutter Inspector ở cạnh phải Android Studio (hoặc View → Tool Windows → Flutter Inspector).
  3. Bật Select Widget Mode, bấm vào phần tử trên app, Inspector sẽ chọn Widget tương ứng trên cây và nhảy tới dòng code tạo ra nó.

5. Lỗi code

5.1. Lỗi biên dịch (gạch đỏ, app không chạy)

Thông báoNguyên nhânCách sửa
Undefined class 'X' / Undefined name 'x' Chưa import file chứa class đó, hoặc gõ sai tên. Đặt con trỏ vào tên đó nhấn Alt + Enter (Mac: Option + Enter) → Import library.
Target of URI doesn't exist: '...' Đường dẫn trong câu import sai, hoặc thư viện ngoài chưa được tải. Kiểm tra lại tên file, thư mục. Nếu là package: của thư viện ngoài: xem lỗi cùng tên ở mục 6.3.
The method 'x' isn't defined for the type 'Y' Gọi hàm không có trong class đó, sai tên hàm, hoặc biến có kiểu khác bạn nghĩ. Kiểm tra tên hàm, Ctrl + Click vào class để xem class có những hàm nào.
A value of type 'String?' can't be assigned to a variable of type 'String' Gán giá trị có thể null (String?) cho biến không được null (String). Đặt giá trị mặc định: name ?? '', hoặc kiểm tra if (name != null) trước khi gán.
Non-nullable instance field 'x' must be initialized Thuộc tính của class không được null nhưng chưa được gán giá trị. Gán trong constructor (required this.x), đặt giá trị mặc định, hoặc khai báo String? x.
The named parameter 'x' is required, but there's no corresponding argument Gọi constructor / hàm mà thiếu tham số bắt buộc required. Truyền thêm tham số đó, ví dụ Note(title: 'abc').
Invalid constant value Dùng const cho Widget mà bên trong có giá trị thay đổi được (biến, controller). Xoá chữ const ở Widget đó.

5.2. Lỗi khi chạy (màn hình đỏ, exception)

Thông báoNguyên nhânCách sửa
Null check operator used on a null value Dùng dấu ! (khẳng định không null) trên biến đang là null. Kiểm tra null trước (if (x != null)), hoặc dùng giá trị mặc định x ?? ... thay cho x!.
LateInitializationError: Field 'x' has not been initialized Biến khai báo late nhưng được đọc trước khi gán giá trị. Gán giá trị trong initState() hoặc trước khi dùng. Nếu không chắc có giá trị: đổi thành biến nullable Type? x.
RangeError (index): Invalid value: Not in inclusive range 0..N Truy cập phần tử ngoài danh sách, ví dụ list[3] khi list chỉ có 3 phần tử (chỉ số 0 đến 2). Kiểm tra index < list.length. Trong ListView.builder phải truyền đúng itemCount: list.length.
type 'Null' is not a subtype of type 'String' Đọc JSON mà key không tồn tại hoặc sai tên, trả về null nhưng gán vào kiểu không null. Kiểm tra tên key đúng với dữ liệu thật, hoặc đặt mặc định: json['name'] ?? ''.
type 'int' is not a subtype of type 'String' (hoặc các cặp kiểu khác) Dữ liệu thật có kiểu khác với kiểu khai báo trong class. Sửa kiểu trong class cho đúng, hoặc chuyển đổi: json['id'].toString().
FormatException: Invalid radix-10 number int.parse() / double.parse() nhận chuỗi không phải số (chuỗi rỗng, có chữ). Dùng int.tryParse(text), trả về null nếu không đổi được, rồi kiểm tra null.
setState() called after dispose() Gọi setState sau khi màn hình đã đóng, thường xảy ra sau một lệnh await (gọi API, đọc DB). Thêm if (!mounted) return; ngay sau await, trước setState.

5.3. Lỗi giao diện (layout)

Thông báo / Hiện tượngNguyên nhânCách sửa
Vạch sọc vàng đen, A RenderFlex overflowed by XX pixels on the bottom/right Nội dung trong Column / Row dài hơn chỗ trống (hay gặp khi bàn phím ảo bật lên). Bọc Column bằng SingleChildScrollView, hoặc bọc phần tử con bằng Expanded / Flexible.
Vertical viewport was given unbounded height Đặt ListView / GridView trực tiếp trong Column, không giới hạn chiều cao. Đặt con trỏ vào ListView → Alt + Enter → Wrap with Expanded.
An InputDecorator, which is typically created by a TextField, cannot have an unbounded width Đặt TextField trực tiếp trong Row, TextField không biết rộng bao nhiêu. Bọc TextField bằng Expanded, hoặc SizedBox(width: ...).
Incorrect use of ParentDataWidget Dùng Expanded / Flexible không nằm trực tiếp trong Row / Column, hoặc Positioned không nằm trực tiếp trong Stack. Chuyển Widget đó ra làm con trực tiếp của Row / Column / Stack.
No Material widget found Dùng TextField, ListTile... mà bên ngoài không có Scaffold hoặc Material. Bọc màn hình bằng Scaffold.

6. Lỗi nền tảng

6.1. Cài đặt SDK và Android Studio

Thông báo / Hiện tượngNguyên nhânCách sửa
flutter: command not found (Linux, macOS) hoặc 'flutter' is not recognized as an internal or external command (Windows) Chưa thêm flutter/bin vào PATH, thêm sai đường dẫn, hoặc chưa mở lại Terminal sau khi thêm. Làm lại phần PATH ở Phần 1, mục 1 theo đúng hệ điều hành, kiểm tra đường dẫn có thư mục bin, rồi mở Terminal mới.
Dart SDK is not configured hoặc không có nút New Flutter Project Chưa cài plugin Flutter hoặc chưa khai báo Flutter SDK path. Làm lại bước 2 và 3 ở Phần 1, mục 1.
cmdline-tools component is missing khi chạy flutter doctor Android SDK thiếu bộ công cụ dòng lệnh. Android Studio: Settings → Languages & Frameworks → Android SDK → tab SDK Tools → tick Android SDK Command-line Tools → Apply. Sau đó chạy flutter doctor --android-licenses.
Android licenses not accepted khi chạy flutter doctor Chưa đồng ý điều khoản Android SDK. Chạy flutter doctor --android-licenses, gõ y cho tất cả.
Waiting for another flutter command to release the startup lock Một lệnh flutter khác đang chạy (thường do Android Studio đang pub get). Đợi lệnh kia xong. Nếu treo lâu: tắt Android Studio và các tiến trình dart, chạy lại.

6.2. Thiết bị và chạy app

Thông báo / Hiện tượngNguyên nhânCách sửa
Device Selector hiện <no devices> Chưa mở emulator, chưa cắm máy thật hoặc chưa bật USB debugging. Mở emulator trong Device Manager, hoặc chạy flutter devices để kiểm tra.
Sửa code rồi Hot Reload nhưng app không thay đổi Sửa ở chỗ Hot Reload không chạy lại: main(), initState(), giá trị khởi tạo. Dùng Hot Restart. Xem bảng ở Phần 1, mục 6.

6.3. Thư viện và build

Thông báo / Hiện tượngNguyên nhânCách sửa
Lỗi khi Pub get: Error on line X, column Y trong pubspec.yaml Sai thụt lề YAML, dùng Tab, hoặc thiếu dấu :. Xem đúng dòng báo lỗi, thụt lề bằng dấu cách, mỗi cấp 2 dấu cách.
Target of URI doesn't exist: 'package:ten_thu_vien/...' Đã khai báo thư viện trong pubspec.yaml nhưng chưa tải về, hoặc chưa khai báo. Kiểm tra thư viện có trong dependencies, rồi chạy flutter pub get.
MissingPluginException sau khi thêm thư viện Thư viện có code native nhưng app chưa được build lại. Stop app rồi Run lại (Hot Restart không đủ).
Build Android lần đầu rất lâu hoặc lỗi Gradle lạ Gradle đang tải công cụ lần đầu, hoặc cache build bị hỏng. Lần đầu cần mạng và chờ. Nếu lỗi: chạy bộ lệnh làm sạch bên dưới.
bash - Bộ lệnh làm sạch khi gặp lỗi build khó hiểu
# Xoá thư mục build/ và .dart_tool/
flutter clean

# Tải lại thư viện
flutter pub get

# Chạy lại
flutter run

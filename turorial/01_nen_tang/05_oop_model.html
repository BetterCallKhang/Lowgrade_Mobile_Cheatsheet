Phần 5. Lập trình Hướng đối tượng (OOP) & Model Dữ liệu JSON

Hướng dẫn toàn diện về OOP trong Dart: Class, Constructor chuẩn, Initializer list, Getter/Setter, Kế thừa, Interface ngầm định, Mixin, Extension Methods (Mở rộng chức năng), và kiến trúc chuẩn của một Model dữ liệu thực chiến với fromJson / toJson.

1. Class, Thuộc tính Private và Các loại Constructor

Khái niệm

Trong Dart, không có từ khoá private hay public. Mọi thuộc tính hoặc class bắt đầu bằng dấu gạch dưới _ (ví dụ: _gender, _id) sẽ mặc định là thư viện cục bộ (library-private), chỉ truy cập được bên trong cùng một file.

Loại ConstructorCú pháp DartMục đích sử dụng
Generative (Chuẩn ngắn gọn) Student(this.id, this.name, this._gender); Gán trực tiếp giá trị tham số vào thuộc tính mà không cần viết thân hàm { this.id = id; }.
Named Constructor (Có tên) Student.guest(...) hoặc Student.empty() Cho phép định nghĩa nhiều cách khởi tạo khác nhau cho cùng một class (thay thế nạp chồng hàm / constructor overloading).
Initializer List Student.guest() : id = 'G01', name = 'Khách'; Khởi tạo giá trị cho thuộc tính trước khi thân hàm constructor thực sự chạy. Rất quan trọng với biến final.
Factory Constructor factory Student.fromJson(Map<String, dynamic> json) Không nhất thiết phải tạo mới một instance mới hoàn toàn; có thể trả về một instance từ cache, trả về lớp con, hoặc parse từ JSON.
dart - Minh hoạ Class, Constructor, Getter & Setter (Student.dart)
class Student {
  String id;
  String name;
  int _gender; // Bắt đầu bằng _ là private (chỉ dùng trong file này)

  // 1. Constructor ngắn gọn theo chuẩn Dart
  Student(this.id, this.name, this._gender);

  // 2. Named constructor + Initializer list (khởi tạo trước khi thân hàm chạy)
  Student.guest()
      : id = 'GUEST_01',
        name = 'Khách vãng lai',
        _gender = 0;

  // 3. Getter: Truy cập thuộc tính private từ bên ngoài
  int get gender => _gender;

  // 4. Setter: Kiểm tra hợp lệ dữ liệu trước khi gán
  set gender(int val) {
    if (val < 0 || val > 1) {
      _gender = 0; // Mặc định 0 nếu truyền giá trị không hợp lệ
    } else {
      _gender = val;
    }
  }

  void displayInfo() {
    print('Student: $id | Tên: $name | Giới tính: $_gender');
  }
}

void main() {
  // Sử dụng generative constructor
  var s1 = Student('SE123', 'Jon', 1);
  s1.gender = -5; // Gọi setter validate -> gán về 0
  s1.displayInfo();

  // Sử dụng named constructor
  var s2 = Student.guest();
  s2.displayInfo();
}

2. Kế thừa (Inheritance), Giao diện (Interface) và Mixin

Khái niệm

Dart là ngôn ngữ đơn kế thừa cho class (chỉ có thể extends 1 cha), nhưng cho phép triển khai nhiều interface (implements) và chia sẻ hành vi đa lớp thông qua Mixin (with).

Từ khoáMục đíchQuy tắc cốt lõi trong Dart
extends Kế thừa class cha hoặc abstract class. Chỉ kế thừa đúng 1 class. Dùng super(...) để gọi constructor và hàm của cha.
implements Hiện thực hoá interface (hợp đồng hàm). Mọi class trong Dart đều ngầm định là một interface! Có thể implements nhiều class, nhưng bắt buộc phải @override lại toàn bộ thuộc tính và phương thức.
mixin & with Tái sử dụng logic code ở nhiều class độc lập mà không cần phân cấp cây kế thừa. Dùng with MixinA, MixinB. Nếu 2 mixin trùng tên phương thức, mixin khai báo sau cùng sẽ ghi đè (override) các mixin trước.
dart - Kế thừa, Mixin và Interface thực chiến (animal.dart)
// 1. Khai báo Interface (Abstract class)
abstract class Printable {
  void printInfo();
}

// 2. Khai báo 2 Mixin độc lập
mixin Flyable {
  void fly() => print('Đang bay trên trời...');
  void prepare() => print('Chuẩn bị sải cánh...');
}

mixin Swimmable {
  void swim() => print('Đang bơi dưới nước...');
  void prepare() => print('Chuẩn bị xuống nước...');
}

// 3. Class cha
class Animal {
  String name;
  Animal(this.name);
}

// 4. Duck: Kế thừa Animal, tái sử dụng Flyable & Swimmable, tuân thủ Printable
class Duck extends Animal with Flyable, Swimmable implements Printable {
  int age;

  Duck(String name, this.age) : super(name);

  @override
  void printInfo() {
    print('Vịt: $name, $age tuổi');
  }
}

void main() {
  var d = Duck('Donald', 3);
  d.printInfo();
  d.fly();
  d.swim();
  
  // Gọi prepare(): Swimmable đứng sau cùng nên hàm prepare() của Swimmable sẽ chạy
  d.prepare(); // In ra: "Chuẩn bị xuống nước..."
}

3. Extension Methods (Mở rộng phương thức cho Class có sẵn)

Khái niệm & Ứng dụng

Extension Methods (từ khoá extension on Type) cho phép bạn bổ sung thêm hàm hoặc getter vào bất kỳ class nào (kể cả các class có sẵn của Dart hoặc Flutter SDK như String, DateTime, BuildContext, int) mà không cần phải sửa mã nguồn gốc hay dùng kế thừa.

Trong Flutter thực tế, Extension được dùng khắp nơi để: định dạng tiền tệ VNĐ, viết hoa chữ cái đầu, validate email, hoặc rút gọn Theme.of(context) và MediaQuery.of(context).

Cú pháp khai báoÝ nghĩaVí dụ gọi hàm
extension TenExtension on String { ... } Mở rộng tính năng cho chuỗi String. 'khang'.capitalize() // "Khang"
extension on DateTime { ... } Mở rộng tính năng format ngày tháng. DateTime.now().toVnDate() // "04/11/2026"
extension on BuildContext { ... } Rút gọn truy cập Theme, kích thước màn hình trong Flutter. context.width // MediaQuery.of(context).size.width
dart - Các Extension thực chiến cực hay dùng trong dự án Flutter
// ==================== 1. EXTENSION TRÊN STRING ====================
extension StringExtensions on String {
  // Viết hoa chữ cái đầu tiên
  String capitalize() {
    if (isEmpty) return this;
    return '${this[0].toUpperCase()}${substring(1)}';
  }

  // Kiểm tra email hợp lệ
  bool get isValidEmail {
    return RegExp(r'^[\w-\.]+@([\w-]+\.)+[\w-]{2,4}$').hasMatch(this);
  }

  // Chuyển chuỗi sang số nguyên an toàn (không lo văng lỗiFormatException)
  int toIntOrZero() {
    return int.tryParse(this) ?? 0;
  }
}

// ==================== 2. EXTENSION TRÊN SỐ (INT / DOUBLE) ====================
extension CurrencyFormat on num {
  // Định dạng số thành chuỗi tiền tệ VND: 50000 -> "50.000 đ"
  String toVnd() {
    return '${toString().replaceAllMapped(RegExp(r'(\d{1,3})(?=(\d{3})+(?!\d))'), (m) => '${m[1]}.')} đ';
  }
}

//   // Lấy nhanh Theme:

void main() {
  // Sử dụng tự nhiên như phương thức nội tại của String và int:
  String title = 'flutter developer';
  print(title.capitalize()); // "Flutter developer"

  String email = 'user@gmail.com';
  print(email.isValidEmail);  // true

  int price = 1500000;

}

4. Model Dữ liệu và Chuẩn hoá JSON (fromJson / toJson)

Khái niệm

Trong ứng dụng Flutter thực tế, dữ liệu nhận về từ REST API hoặc cơ sở dữ liệu SQLite đều ở dạng Map<String, dynamic>. Để code chặt chẽ, dễ bảo trì và gợi ý code tốt (type-safe), ta luôn tạo Model Class với cặp phương thức fromJson và toJson.

Cấu trúc chuẩn của một Model Class trong Flutter
dart - Post.dart (Model chuẩn bài thi PE & Dự án thực tế)
class Post {
  final int userId;
  final int id;
  final String title;
  final String body;

  // Constructor với Named Parameters & required
  Post({
    required this.userId,
    required this.id,
    required this.title,
    required this.body,
  });

  // 1. fromJson: Chuyển đổi từ Map (JSON) sang Object Post
  // Sử dụng 'as ...? ?? fallback' để chống crash khi trường bị null hoặc sai kiểu
  factory Post.fromJson(Map json) {
    return Post(
      userId: json['userId'] as int? ?? 0,
      id: json['id'] as int? ?? 0,
      title: json['title'] as String? ?? '',
      body: json['body'] as String? ?? '',
    );
  }

  // 2. toJson: Chuyển đổi từ Object Post sang Map để gửi POST/PUT lên API hoặc lưu SQLite
  Map toJson() {
    return {
      'userId': userId,
      'id': id,
      'title': title,
      'body': body,
    };
  }

  // 3. toString: Tiện lợi khi debug in log ra Terminal
  @override
  String toString() {
    return 'Post{id: $id, title: $title, userId: $userId}';
  }
}

5. Bảng tổng kết và các lỗi OOP hay gặp

Vấn đề / Cú phápNguyên nhân / Bản chấtGiải pháp chuẩn
extension on Type Thêm phương thức mở rộng cho class có sẵn mà không thể hoặc không muốn sửa code nguồn. Dùng để format tiền tệ price.toVnd(), viết hoa str.capitalize(), validate dữ liệu.
factory constructor Không tự động tạo instance rỗng mà phải trả về một instance cụ thể (return Post(...)). Dùng cho fromJson hoặc Singleton Pattern quản lý Database.
Lỗi: Field must be initialized Biến final không được phép null nhưng chưa có giá trị ban đầu. Khai báo required this.field trong constructor hoặc dùng Initializer List : field = ....
Xung đột hàm trong Mixin Nhiều mixin cùng chứa hàm trùng tên. Mixin nào đứng sau cùng trong danh sách with M1, M2 sẽ có độ ưu tiên cao nhất và ghi đè các mixin trước.
Ép kiểu as bị crash lúc chạy Dữ liệu JSON trả về kiểu double nhưng ép thành as int (hoặc bị null). Dùng (json['price'] as num?)?.toDouble() ?? 0.0 để an toàn cả int lẫn double.

Bước 2: Phương Pháp Suy Luận & Xây Dựng Data Models Chuẩn Phòng Thi

Sau khi đã setup xong dự án, nhiệm vụ số 1 về mặt code luôn là tạo các Data Models. Model là "bộ khung xương" định hình toàn bộ dữ liệu của ứng dụng: từ việc tạo bảng SQLite, chuyển đổi dữ liệu khi đọc ghi database, cho đến việc hiển thị lên giao diện hoặc gọi API.

1. Data Model Là Gì? Vì Sao Phải Tạo Model Trước Tiên?

Bản chất của Model

Model (Lớp mô hình dữ liệu) là một class trong Dart đại diện cho một đối tượng trong đời thực được số hóa (ví dụ: một người dùng User, một bức tranh Artwork, một sản phẩm Product).

Khi làm việc với CSDL SQLite hoặc REST API, dữ liệu thô luôn ở dạng Map<String, dynamic> (các cặp key - value như {"id": 1, "title": "Mona Lisa"}). Nếu cứ dùng trực tiếp biến Map:

  • Rất dễ gõ sai chính tả tên key: item['titel'] thay vì item['title'] dẫn đến lỗi null hoặc sập app khi chạy.
  • Không có gợi ý code (IntelliSense) từ Android Studio / VS Code.
  • Khi có Model: Bạn chỉ cần chấm artwork.title, máy sẽ gợi ý code tức thì và kiểm tra lỗi sai kiểu dữ liệu ngay lúc gõ phím!

2. Phương Pháp Suy Luận: Cách Đọc Đề Bài & Soi dataSample.txt

Khi cầm đề thi trên tay, làm thế nào để biết Model cần bao nhiêu trường (fields), trường nào được phép null, trường nào là khóa chính?

Bước A: Đọc bảng thông số ở mục "2. Data Models" của đề bài

Đề bài thi luôn có 2 bảng biểu rõ ràng:

Bảng 2.1 User Model (Người dùng)
  • id (int) → User ID (Primary Key)
  • username (String) → Tên đăng nhập
  • email (String) → Email người dùng
  • password (String) → Mật khẩu
  • createdAt (String) → Ngày tạo tài khoản
Bảng 2.2 Artwork Model (Bức tranh)
  • id (int) → Artwork ID (Primary Key)
  • title (String) → Tên tác phẩm
  • artist (String) → Tên tác giả
  • year (int) → Năm sáng tác
  • category (String) → Thể loại tranh
  • description (String) → Mô tả chi tiết
  • createdBy (int) → Khóa ngoại trỏ đến User ID

Bước B: Soi file tài nguyên dataSample.txt (Đề thi cấp)

Mở file dataSample.txt trong thư mục material/. File này cho bạn biết cấu trúc JSON thực tế mà giảng viên dùng để chấm điểm:

{
  "users": [
    {
      "id": 1,
      "username": "admin",
      "email": "admin@gallery.com",
      "password": "123456",
      "createdAt": "2026-01-10"
    }
  ],
  "artworks": [
    {
      "id": 1,
      "title": "Starry Night",
      "artist": "Vincent van Gogh",
      "year": 1889,
      "category": "Abstract",
      "description": "A famous Abstract of a swirling night sky over a small town.",
      "createdBy": 1
    }
  ]
}
ĐÚC KẾT SUY LUẬN TỐI QUAN TRỌNG:
  1. Trường id: Khi tạo mới (Insert) vào SQLite thì id sẽ do cơ sở dữ liệu tự tăng (AUTOINCREMENT) nên lúc khởi tạo đối tượng mới để thêm, id có thể là null. Do đó kiểu dữ liệu của id nên là int? (nullable).
  2. Trường createdBy: Đây là khoá ngoại (Foreign Key) liên kết 1-nhiều (User 1 → N Artwork). Khi thêm tranh, giá trị này sẽ lấy từ ID của tài khoản đang đăng nhập!
  3. Tên các thuộc tính trong class Dart: Phải khớp 100% từng chữ hoa/thường (camelCase) với các key trong JSON và tên cột trong SQLite: createdAt, createdBy.

3. "Công Thức Vàng" Của Một Data Model Chuẩn Phòng Thi

Mỗi một file Model trong lib/models/ luôn tuân theo đúng 5 thành phần bất hủ sau:

1. Các thuộc tính (Fields)

Khai báo final cho tất cả thuộc tính để đảm bảo tính bất biến (Immutable), riêng id để int?.

2. Constructor chuẩn (Named Parameters)

Dùng ngoặc nhọn {this.id, required this.username, ...} giúp khi gọi tạo đối tượng cực kỳ rõ ràng.

3. Hàm toMap() (hoặc toJson())

Biến đối tượng Model thành Map<String, dynamic> để đẩy vào SQLite (Insert/Update) hoặc gửi lên API (POST).

4. Hàm fromMap() (hoặc fromJson())

Là Factory Constructor nhận vào một dòng dữ liệu từ SQLite (Map) và trả về đối tượng Model để giao diện vẽ lên màn hình.

4. Thực Hành Tạo Model 1: User (Tài Khoản Người Dùng)

Tạo file: lib/models/user_model.dart

// lib/models/user_model.dart

class UserModel {
  final int? id;             // Khóa chính (Primary Key), tự tăng nên có thể null khi tạo mới
  final String username;     // Tên đăng nhập (duy nhất)
  final String email;        // Email người dùng
  final String password;     // Mật khẩu
  final String createdAt;    // Ngày tạo tài khoản (dạng chuỗi YYYY-MM-DD)

  // 1. Constructor khởi tạo với named parameters
  UserModel({
    this.id,
    required this.username,
    required this.email,
    required this.password,
    required this.createdAt,
  });

  // 2. Chuyển từ Model thành Map để lưu vào SQLite (hoặc gửi lên API)
  Map toMap() {
    return {
      'id': id,
      'username': username,
      'email': email,
      'password': password,
      'createdAt': createdAt,
    };
  }

  // 3. Khởi tạo Model từ dữ liệu Map đọc từ SQLite lên (hoặc nhận về từ API)
  factory UserModel.fromMap(Map map) {
    return UserModel(
      id: map['id'] as int?,
      username: map['username'] ?? '',
      email: map['email'] ?? '',
      password: map['password'] ?? '',
      createdAt: map['createdAt'] ?? '',
    );
  }

  // 4. (Tùy chọn) copyWith để tạo bản sao khi cần cập nhật 1 vài trường dữ liệu
  UserModel copyWith({
    int? id,
    String? username,
    String? email,
    String? password,
    String? createdAt,
  }) {
    return UserModel(
      id: id ?? this.id,
      username: username ?? this.username,
      email: email ?? this.email,
      password: password ?? this.password,
      createdAt: createdAt ?? this.createdAt,
    );
  }
}

5. Thực Hành Tạo Model 2: Artwork (Tác Phẩm Tranh / Thực Thể CRUD)

Tạo file: lib/models/artwork_model.dart

// lib/models/artwork_model.dart

class ArtworkModel {
  final int? id;             // Khóa chính tự tăng (id tự sinh trong CSDL)
  final String title;        // Tên bức tranh
  final String artist;       // Tác giả
  final int year;            // Năm sáng tác
  final String category;     // Thể loại (ví dụ: Abstract, Modern, Landscape...)
  final String description;  // Mô tả bức tranh
  final int createdBy;       // ID người tạo (Khóa ngoại liên kết với User)

  // 1. Constructor
  ArtworkModel({
    this.id,
    required this.title,
    required this.artist,
    required this.year,
    required this.category,
    required this.description,
    required this.createdBy,
  });

  // 2. Chuyển Model thành Map để INSERT / UPDATE vào CSDL SQLite
  Map toMap() {
    return {
      'id': id,
      'title': title,
      'artist': artist,
      'year': year,
      'category': category,
      'description': description,
      'createdBy': createdBy,
    };
  }

  // 3. Chuyển từ Map đọc từ CSDL thành Model hiển thị lên giao diện
  // Lưu ý: Dùng `int.tryParse()` để phòng hờ trường hợp dữ liệu year bị trả về dạng chuỗi
  factory ArtworkModel.fromMap(Map map) {
    return ArtworkModel(
      id: map['id'] as int?,
      title: map['title'] ?? '',
      artist: map['artist'] ?? '',
      year: map['year'] is int ? map['year'] : (int.tryParse(map['year'].toString()) ?? 0),
      category: map['category'] ?? '',
      description: map['description'] ?? '',
      createdBy: map['createdBy'] is int ? map['createdBy'] : (int.tryParse(map['createdBy'].toString()) ?? 0),
    );
  }

  // 4. copyWith hỗ trợ cập nhật dữ liệu một cách an toàn
  ArtworkModel copyWith({
    int? id,
    String? title,
    String? artist,
    int? year,
    String? category,
    String? description,
    int? createdBy,
  }) {
    return ArtworkModel(
      id: id ?? this.id,
      title: title ?? this.title,
      artist: artist ?? this.artist,
      year: year ?? this.year,
      category: category ?? this.category,
      description: description ?? this.description,
      createdBy: createdBy ?? this.createdBy,
    );
  }
}

6. Bảng Tra Cứu Kiểu Dữ Liệu: Dart vs SQLite vs JSON

Lỗi phổ biến nhất của sinh viên khi làm bài thi là ép sai kiểu dữ liệu dẫn đến app bị sập màn hình đỏ (Crash) ngay khi vừa load CSDL. Hãy đối chiếu bảng sau:

Khái niệm / Loại dữ liệu Kiểu dữ liệu trong Dart Kiểu cột trong SQLite Dạng giá trị trong JSON Cách parse an toàn trong fromMap
Số nguyên (ID, Năm, Số lượng) int hoặc int? INTEGER 1889 (số) int.tryParse(map['year'].toString()) ?? 0
Số thực (Giá tiền, Rating) double hoặc double? REAL 99.99 (số thực) double.tryParse(map['price'].toString()) ?? 0.0
Văn bản, Ngày tháng, URL ảnh String TEXT "2026-01-10" (chuỗi) map['title']?.toString() ?? ''
Đúng / Sai (Boolean) bool INTEGER (0 hoặc 1) true / false hoặc 1 / 0 map['isCompleted'] == 1 || map['isCompleted'] == true
KẾT QUẢ BƯỚC 2:

Bạn đã hoàn thành 2 file Model nền tảng trong lib/models/: user_model.dart và artwork_model.dart. Bạn đã hiểu rõ bản chất tại sao phải có toMap() (để chuẩn bị ghi vào SQLite) và fromMap() (để đọc từ SQLite ra). Giờ đây, việc tạo DatabaseHelper ở bước tiếp theo sẽ cực kỳ trơn tru!

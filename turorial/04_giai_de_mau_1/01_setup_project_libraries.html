Bước 1: Khởi Tạo Dự Án & Cấu Hình Bộ Thư Viện Dùng Chung Cho Mọi Đề Thi

Đây là kim chỉ nam đầu tiên khi bạn bước vào phòng thi thực hành Mobile Flutter. Dù đề bài yêu cầu quản lý Tranh ảnh (Art Gallery), Sách (Bookstore), Sinh viên (Student Management), Sản phẩm (E-commerce) hay Khách sạn... thì thao tác khởi tạo dự án và khai báo các package cốt lõi luôn luôn theo một quy chuẩn thống nhất.

Tài liệu này được biên soạn tỉ mỉ theo phương châm "người chưa biết gì đọc vào cũng hiểu và làm được ngay", cung cấp chính xác phiên bản các thư viện chuẩn (SQLite, Web FFI, Shared Preferences, Riverpod Code Generator, HTTP), giải thích rõ ràng và có sẵn mã copy nhanh không lo lỗi thụt dòng.

Nội dung hướng dẫn Bước 1 gồm 7 phần chi tiết:
  • 1. Quy tắc sống còn trong phòng thi PE (Tránh bị 0 điểm oan)
  • 2. Khởi tạo dự án Flutter linh hoạt theo tên yêu cầu của từng đề thi
  • 3. Danh mục phiên bản các thư viện chuẩn (Mobile & Web Test)
  • 4. File pubspec.yaml hoàn chỉnh & Lệnh cài đặt nhanh qua Terminal
  • 5. Cấu hình Assets (Hình ảnh, Banner, Logo đề thi cấp)
  • 6. Cấu trúc thư mục chuẩn trong lib/ (Gọn gàng, dễ chấm điểm)
  • 7. Checklist kiểm tra hoàn thành Bước 1

1. Quy Tắc Sống Còn Trong Phòng Thi PE

4 NGUYÊN TẮC BẤT DI BẤT DỊCH CẦN KHẮC CỐT GHI TÂM:
  1. Tên dự án theo đề bài: Đề bài thi KHÔNG BAO GIỜ cố định 1 tên duy nhất. Tùy học kỳ và ca thi, đề bài sẽ chỉ định: sp26studentcode, fa25studentcode, hoặc chính mã sinh viên của bạn (ví dụ: se171234, he180999). Bạn phải đọc kỹ mục "Project folder name" ở trang 1 đề thi và đặt tên cho chính xác.
  2. Quy tắc đặt tên dự án Flutter: Phải viết chữ thường, không viết hoa, không dấu tiếng Việt, không chứa khoảng trắng hay ký tự đặc biệt (chỉ dùng chữ cái, số và dấu gạch dưới _ nếu cần). Ví dụ: se170001_exam hoặc sp26studentcode.
  3. Chạy thử dự án ban đầu (Run F5): Tạo xong dự án phải bấm F5 chạy thử ngay. Nếu máy thi bị treo giả lập hoặc lỗi môi trường thì báo ngay cho giám thị đổi máy trước khi làm bài.
  4. DỌN DẸP DỰ ÁN TRƯỚC KHI NỘP: Khi hết giờ làm bài, bắt buộc phải mở Terminal tại dự án và gõ lệnh: flutter clean. Lệnh này sẽ xoá các file cache build tạm nặng hàng trăm MB, giúp file zip nén lại chỉ còn vài trăm KB đến 1-2 MB, tránh bị giám thị huỷ bài hoặc lỗi hệ thống nộp bài EOS/Cổng thi.

2. Khởi Tạo Dự Án Flutter Linh Hoạt Theo Từng Đề Thi

Cách 1: Sử dụng Terminal / Dòng lệnh (Nhanh nhất & Tuyệt đối chính xác)

Mở Terminal (trên Windows là PowerShell / Git Bash / Command Prompt) tại thư mục được chỉ định lưu bài (thường là ổ D: hoặc Desktop theo hướng dẫn của giám thị):

# Cú pháp tổng quát: flutter create 

# Trường hợp 1: Đề yêu cầu đặt theo cú pháp học kỳ + studentcode
flutter create sp26studentcode

# Trường hợp 2: Đề yêu cầu đặt theo Mã số sinh viên của bạn
# flutter create se171234

# Di chuyển ngay vào thư mục vừa tạo
cd sp26studentcode

# Mở dự án lên bằng VS Code (hoặc mở bằng Android Studio)
code .

Cách 2: Sử dụng giao diện đồ hoạ Android Studio

1
Khởi chạy Android Studio & Tạo New Project

Mở Android Studio → Bấm nút New Flutter Project (hoặc trên thanh Menu chọn File → New → New Flutter Project).

2
Kiểm tra SDK & Điền thông tin đề bài

Đảm bảo ô Flutter SDK path đã nhận diện SDK → Nhấn Next.

Ở ô Project name: Nhập đúng tên đề bài yêu cầu (ví dụ: sp26studentcode hoặc mã SV của bạn). Chọn thư mục lưu bài thi → Nhấn Create.

Nhóm Chức Năng Package & Phiên Bản Chuẩn Vai Trò & Lưu Ý Phòng Thi
Cơ sở dữ liệu SQLite (Mobile) sqflite: ^2.4.2

riverpod_annotation: ^4.0.1 		Bộ State Management reactive hiện đại, cung cấp ProviderScope, ConsumerWidget, ref.watch, ref.read giúp chia sẻ dữ liệu toàn app mượt mà.
Công cụ sinh code tự động (Dev) build_runner:

Ghi đè xung đột phiên bản test_api: ^0.7.9 Nằm trong dependency_overrides: Ngăn chặn triệt để lỗi đỏ xung đột package giữa Flutter SDK và Riverpod Generator.

4. File pubspec.yaml Hoàn Chỉnh & Lệnh Cài Đặt Nhanh

Cách 1: Sao chép nguyên khối vào file pubspec.yaml (Chuẩn xác 100%)

Mở file pubspec.yaml ở thư mục gốc của dự án vừa tạo, thay thế nội dung các khối dependencies, dev_dependencies, dependency_overrides bằng khối dưới đây:

name: my_exam_project
description: "Flutter Exam Practical Project"
publish_to: 'none'
version: 1.0.0+1

environment:
  sdk: ^3.5.0

dependencies:
  flutter:
    sdk: flutter

  # ========================================================
  # 1. CƠ SỞ DỮ LIỆU SQLITE (MOBILE + WEB BROWSER TEST)
  # ========================================================
  sqflite: ^2.4.2
  path: ^1.9.1
  # Thư viện SQLite chạy trên Web Browser (Chrome/Edge khi máy ảo lag)
  sqflite_common_ffi_web:

  # ========================================================
  # 2. LƯU TRỮ PHIÊN ĐĂNG NHẬP (SESSION MANAGEMENT)
  # ========================================================
  shared_preferences: ^2.5.4

  # ========================================================
  # 3. QUẢN LÝ TRẠNG THÁI (STATE MANAGEMENT - RIVERPOD)
  # ========================================================
  flutter_riverpod: ^3.2.0
  riverpod_annotation: ^4.0.1

  # ========================================================
  # 4. KẾT NỐI MẠNG REST API (NẾU ĐỀ YÊU CẦU FETCH API)
  # ========================================================
  http: ^1.2.0

  # Icon chuẩn Material & iOS
  cupertino_icons: ^1.0.8

dev_dependencies:
  flutter_test:
    sdk: flutter
  flutter_lints: ^6.0.0

  # Công cụ sinh mã tự động cho Riverpod (.g.dart)
  build_runner:
  riverpod_generator: ^4.0.2

# Chặn xung đột phiên bản test_api với Flutter SDK mới
dependency_overrides:
  test_api: ^0.7.9

flutter:
  uses-material-design: true

  # Khai báo đường dẫn tài nguyên hình ảnh đề thi
  assets:
    - assets/images/

Cách 2: Cài đặt từng phần qua dòng lệnh Terminal

Nếu bạn muốn gõ lệnh tự động tải package mà không cần mở file:

# 1. Thêm SQLite, Shared Preferences, Riverpod và HTTP:
flutter pub add sqflite:^2.4.2 path:^1.9.1 sqflite_common_ffi_web shared_preferences:^2.5.4 flutter_riverpod:^3.2.0 riverpod_annotation:^4.0.1 http:^1.2.0

# 2. Thêm các công cụ sinh mã dev_dependencies:
flutter pub add dev:build_runner dev:riverpod_generator:^4.0.2 dev:flutter_lints:^6.0.0
Lệnh kích hoạt tải thư viện:

Sau khi lưu file hoặc chạy lệnh, hãy gõ flutter pub get trong Terminal. Khi màn hình hiện exit code 0 nghĩa là tất cả các thư viện đã sẵn sàng hoạt động!

5. Cấu Hình Assets (Hình Ảnh, Banner, Logo Đề Thi Cấp)

Trong đề thi thực hành (như thư mục material/ của đề mẫu), giám thị luôn cấp sẵn các file tài nguyên đi kèm: hình ảnh banner.jpg, logo, hoặc file dataSample.txt chứa dữ liệu mẫu.

1
Tạo thư mục assets/images trong dự án

Tại thư mục gốc của project (ngang hàng với thư mục lib), bạn tạo một thư mục mới tên là assets, bên trong tạo tiếp thư mục images.

2
Sao chép ảnh từ đề bài vào thư mục

Copy toàn bộ file ảnh đề bài cấp (ví dụ banner.jpg) dán vào thư mục assets/images/ vừa tạo.

# Cấu trúc hiển thị trên cây thư mục:
/
  ├── assets/
  │   └── images/
  │       └── banner.jpg    <-- Ảnh banner/logo đề thi cấp
  ├── lib/
  └── pubspec.yaml
3
Khai báo đường dẫn trong pubspec.yaml

Trong pubspec.yaml, dưới mục flutter:, hãy đảm bảo có khai báo:

flutter:
  uses-material-design: true

  assets:
    - assets/images/
Mẹo thi cử: Luôn kết thúc bằng dấu gạch chéo / (ví dụ: - assets/images/). Dấu gạch chéo này báo hiệu cho Flutter nhận diện toàn bộ file ảnh bên trong thư mục, bạn không cần phải khai báo từng tên file lẻ tẻ.

6. Phân Chia Cấu Trúc Thư Mục Chuẩn Trong lib/ (Cho Mọi Đề Thi)

Để code không bị rối và giám khảo chấm bài nhìn vào thấy ngay tính chuyên nghiệp, hãy tạo sẵn 4 thư mục cốt lõi bên trong lib/ ngay từ đầu:

lib/
├── models/         # 1. Chứa các lớp khuôn mẫu dữ liệu (User, Artwork, Product, Book...)
│   ├── user_model.dart
│   └── item_model.dart (hoặc artwork_model tùy theo đề bài)
│
├── database/       # 2. Chứa DatabaseHelper (Khởi tạo SQLite, tạo bảng, câu lệnh CRUD)
│   └── database_helper.dart
│
├── services/       # 3. Chứa gọi API (http) hoặc xử lý Session SharedPreferences
│   ├── api_service.dart
│   └── session_service.dart
│
├── providers/      # 4. Chứa các State Notifier / Riverpod Providers quản lý dữ liệu
│   └── item_provider.dart
│
├── screens/        # 5. Chứa toàn bộ các màn hình giao diện (UI) của từng Task đề yêu cầu
│   ├── login_screen.dart           # Màn hình Đăng nhập (Task 2)
│   ├── register_screen.dart        # Màn hình Đăng ký (Task 1)
│   ├── home_screen.dart            # Màn hình Danh sách chính (Task 4)
│   ├── add_screen.dart             # Màn hình Thêm mới dữ liệu (Task 5)
│   └── detail_screen.dart          # Màn hình Xem chi tiết (Task 6)
│
└── main.dart       # Điểm bắt đầu của ứng dụng (Khởi tạo ProviderScope & Kiểm tra Session)
Lệnh Terminal tạo nhanh trọn bộ cấu trúc thư mục trong 1 giây: 
mkdir -p lib/models lib/database lib/services lib/providers lib/screens assets/images
